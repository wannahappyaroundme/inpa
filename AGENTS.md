## 2. Context

- **Target users:** individually-contracted planners (sole proprietors) at carriers/GAs. Priority 1 = new planners (desperate for lead-gen); priority 2 = mid-career (management).
- **Value:** prospecting → coverage analysis → neutral visual comparison of multiple policies → meeting/relationship management in ONE flow. Analysis is the *start* of the sales action, not a report.
- **Differentiators:** (1) put arbitrary policy sets into fixed `증권 A`/`증권 B` columns and compare premiums/coverages on one factual visual frame without product selection advice; (2) full 100+ coverage (담보) frame + per-carrier coverage-name normalization.
- **BM:** Freemium (all features open, free monthly quota, heavy users subscribe).
- **Org:** CPO = CTO (the user). No external legal counsel → compliance handled conservatively (safe defaults + public regulator/association guides), re-reviewed before paid launch.

## 5. Architecture (big picture, spans multiple files)

### Request flow
Browser → Next page (`inpa_fe/app/**`) → **`inpa_fe/lib/api.ts`** (single BE-call gate: all endpoints+types in one file; admin in `lib/adminApi.ts`) → DRF `/api/v1/` (`config/urls.py` fans out to per-app `urls.py`) → ViewSet → model. `inpa/core/mixins.py::OwnedQuerySetMixin` (filters to own rows + auto-injects owner on create) + `inpa/core/permissions.py::IsOwner`/`IsAdmin`/`IsEmailVerified`. **Owner-scoped ViewSets MUST attach this mixin + IsOwner.** Admin (`profile.is_admin`) bypasses read. ### OCR → analysis pipeline (the core foliio-reuse flow)
Policy PDF upload (`POST /customers/<id>/insurances/ocr/`) → `core/ocr/claude_parser` (pdfplumber + Claude Opus; `ANTHROPIC_API_KEY`-gated, 503 if unset; `max_tokens=8192`) → `CustomerInsuranceDetail` (M2M to standard tree) → `analysis/calculate.py` sums `held_amount` per leaf → if a `PlannerBaseline` matches → `graded` (부족/적정/넉넉); else `neutral` → heatmap/share view.
Normalization SSOT: `core/ocr/ocrparsing.py::COVERAGE_KEYWORDS`, ONE dict shared by both pipelines. Matching = **substring (`if kw in name`) + longest-keyword-first**. Fix mis-matches in dict DATA, not logic (see Gotchas).

Reviewed path (gate closed): upload → sandboxed PDF text extraction → deterministic identity masking → Claude structured extraction from masked lines only → code validation/evidence binding → planner review and optional manual add → atomic confirm into owner-scoped insurance/cases → heatmap/share. A provider result never writes analysis directly. Uncertain/no-evidence/mismatch rows block confirm until a planner explicitly fixes or confirms them. The feature gate must not open from synthetic E2E alone; `docs/dev/27-insurance-review-operations.md` is the release-evidence authority.

## 7. Gotchas (read BEFORE touching the area, these have bitten)

- **`update_fields` + model `save()` hook**: when a `save(update_fields=[...])` is used but the model's `save()` hook sets ANOTHER field (e.g. `Customer.save()` stamps `fa_reached_at` on stage→meeting), that field is NOT written unless it's in `update_fields`. Booking auto-promote includes BOTH (`['sales_stage','fa_reached_at']`). Bit once (2026-06-29). Same trap applies to any hook-derived field.
- **Email verification = BE self-contained token** (`accounts`): `signing.dumps(pk)` → link and verify use `token` ONLY, no `uid` (UNLIKE reset-password). **If FE requires `uid`, signup is fully blocked, do NOT regress.** Resend button exists.
- **Consent token is multi-scope** (`customers/tokens.py`): `make_consent_token(customer, scopes=None)`; `read_consent_token` returns `{pk, scopes}` (legacy bare-int → `{pk, scopes:['overseas_medical']}`, keep compat). `/c` GET → `items[]`; POST `{agreed:[scope]}`; only token-scoped consents recorded (forgery guard); required scope unmet → 412.
- **Consent subject enforcement:** planner-recorded consents are `subject=planner_attested` (server-forced) and CANNOT open the `consent_overseas_at` gate; only `customer_self` (via `/c` or self-diagnosis) opens it. **Registration modal no longer has planner self-check consent boxes**, consent is collected by sending the customer the `/c` link.
- **OCR normalization substring trap** (`core/ocr/ocrparsing.py::COVERAGE_KEYWORDS`): substring + longest-first means a name containing a shorter keyword mis-routes (e.g. '상피내암' contains '암진단'). Fix in dict DATA, NOT the logic. No migration. Add a regression test calling `_match_coverage` directly.
- **Booking timezone:** `availability.py` must keep ALL comparisons in KST aware. WorkHour/recur-block TimeFields are KST wall-clock (combine with the KST date); meetings/single events are UTC (`timezone.localtime`). Mixing them naively shifts 9h.
- **"This month" = KST, not `timezone.now()`** (`dashboard/`): the `__year`/`__month` ORM lookups bucket by `TIME_ZONE`(Asia/Seoul). So any "current month" window MUST use `timezone.localtime()`/`localdate()`, `timezone.now()`(UTC) or `date.today()`(OS-local, e.g. CI=UTC) mis-aligns and drops counts on the UTC/KST month-boundary day. Bit on 2026-07-01 (4 dashboard tests went red at midnight KST). Fixed; apply the same rule to any new monthly aggregation (e.g. `billing` UsageMeter).
- **`NEXT_PUBLIC_API_BASE` build-time inline:** changing it in Vercel needs a redeploy. If prod FE calls localhost, it's unset/not-redeployed.
- **`FRONTEND_BASE_URL` is effectively required** (default `localhost:3000`): unset in prod → email-verify / consent / booking links generate as localhost = broken.
- **New custom domain = 4 env/console updates, ALL env-driven (no code)** (bit 2026-07-01 when `www.inpa.kr` went live → login CORS-blocked, `access-control-allow-origin` absent on preflight while `in-pa.vercel.app` worked): on Render add the new origin to **`CORS_ALLOWED_ORIGINS`** (`prod.py::env.list`, default `[]`) AND **`CSRF_TRUSTED_ORIGINS`**, set **`FRONTEND_BASE_URL`** to the new domain, and add both `https://www.<domain>`+`https://<domain>` (www + apex) since they are distinct origins. Separately, add the domain to the **Google OAuth client's Authorized JavaScript origins** (Google Cloud Console) or the GSI button 403s ("origin not allowed for client ID"). `ALLOWED_HOSTS` = the BE host only (Render auto-injects its own). A 503 right after a merge is usually the Render free-tier redeploy/cold-start, not a real error (check `/healthz/`).
- **402 hidden in beta:** `FREE_TIER_UNLIMITED=True` bypasses all limit checks. BE already returns 402 `{code:'credit_exhausted', kind, limit, used}` for OCR/analysis/compare/promotion. Flipping the flag without an FE notice modal = users see red errors.
- **SQLite vs Postgres seed trap** (memory `sqlite-vs-postgres-seed-trap`): local SQLite ignores varchar length, prod PG rejects. Validate seeds/fixtures against PG too (e.g. `JobRiskCode.name` max 120). Prod `seed_demo` is manual via Render Shell.
- **SEED_VERSION marker trap (2026-07-04):** `seed_normalization`/`seed_jobs` no-op on boot when `SeedMarker` matches the in-code `SEED_VERSION`. Changing seed DATA (STANDARD_TREE, NORMALIZATION_V0, job_risk_codes.json) WITHOUT bumping `SEED_VERSION` means the next deploy silently ships nothing. Bump the constant in the same commit as the data change.
- **`lead_created_at` is the ONLY inbound-lead discriminator (2026-07-04 review blocker):** `lead_source='introduction'`(소개) is planner-selectable in the create/bulk modals, so NEVER treat `lead_source` alone as "came from /d //p". Only the inbound flows set `lead_created_at`; the 6-month retention purge (`cleanup_expired_leads`) requires it non-null plus 4 more AND-guards, keep that shape for any future lead logic.
- **Next 16 nested-layout openGraph trap (2026-07-05):** defining `openGraph` in a nested layout REPLACES the parent's resolved object, the root `app/opengraph-image.jpg` file-convention image silently drops off those routes. Public token layouts therefore set images explicitly via `lib/public-og.ts` (resolved absolute through root `metadataBase`). Use that builder for any new public route; verified by curl on all 5 token routes.
- **Consent doc-version gate (2026-07-04):** the OCR/medical 412 gates require a `customer_self` overseas ConsentLog with `doc_version == CONSENT_TEXTS_VERSION` (`customers/consent_texts.py`). Changing consent WORDING substantively ⇒ bump the version ⇒ every existing customer must re-consent via /c or /d before NEW Claude calls (by design). Never edit consent copy inline in views/FE, the module is the single source.
- **Neutral comparison labels (2026-07-20):** every rendered surface must use `여러 증권 비교`, `증권 A`, and `증권 B`. Never infer semantic roles from `portfolio_type` for display labels. Backend fields such as `current`/`proposed` and billing telemetry keys remain compatibility contracts only; do not expose those names as user-facing current/proposal copy.
