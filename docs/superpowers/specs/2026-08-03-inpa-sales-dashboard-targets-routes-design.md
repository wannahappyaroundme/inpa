# 인파 실행판 원수사 80곳·위치·동선 통합 설계

작성일: 2026-08-03  
대상 파일: `docs/strategy/inpa-sales-marketing-execution.html`

## 1. 목표

기존 단일 HTML 실행판에 조사 완료된 원수사 영업거점 80곳, 우선 40곳, 8월 날짜별 행동, 8~12월 목표, 건물별 동선, 선정 기준과 공식 출처를 모두 옮긴다. 두 명의 운영자가 파일을 열고 30초 안에 오늘 연락할 곳, 첫 방문지, 다음 동선, 사용할 영업 시나리오와 완료 기준을 결정할 수 있어야 한다.

최종 성과는 방문 횟수가 아니라 실제 기능 사용과 반복 피드백이 확인된 사용자 20명이다.

## 2. 현재 구조와 유지 조건

- 기존 실행판은 외부 서버·로그인·빌드가 없는 단일 HTML이다.
- 오늘 체크리스트, 월간 캘린더, KPI, 영업 대상, 설계파트너, 시나리오, 회고를 제공한다.
- 브라우저 저장 키 `inpa-sales-marketing-execution-v1`을 사용한다.
- JSON 내보내기·불러오기, 기본 계획 복원, 인쇄 기능을 유지한다.
- 기존 사용자가 수정한 일정·체크·대상·파트너·시나리오·회고를 초기화하지 않는다.
- 기존 인파 프런트엔드와 백엔드에는 연결하지 않는다.

## 3. 확정한 정보 구조

상단 메뉴는 앵커 링크 모음이 아니라 활성 화면만 표시하는 5개 메인 탭으로 바꾼다. 마지막으로 선택한 탭은 브라우저에 저장한다.

### 3.1 오늘 실행

- 오늘 반드시 할 일, 시간이 되면 할 일, 기한이 지난 후속을 구분한다.
- 각 항목에 날짜, 거점, 담당자, 목표, 실적, 다음 행동, 완료 체크를 제공한다.
- 당일 방문 계획이 있으면 출발지, 첫 방문, 다음 방문과 준비물을 상단에 표시한다.
- 현재 단계에 맞는 시나리오를 해당 카드에서 바로 열 수 있게 한다.
- 8월 3일부터 28일까지는 엑셀의 날짜별 완료 기준을 기본 일정으로 사용한다.
- 9월부터 12월까지는 기존 전국 확장·유지 일정을 이어서 사용한다.

### 3.2 대상 관리

하위 보기 `원수사 거점`과 `설계파트너`를 제공한다.

원수사 거점에는 다음을 제공한다.

- 우선 40곳 / 전체 80곳 전환
- 검색 및 회사, 생명·손해, 권역, 건물, 우선 단계, 실행주차, 연락상태, 미팅상태 필터
- 순위, 회사, 전속조직, 지점, 전화, 주소, 건물, 공식 출처, 확인일
- 관리직 효과, 설계사 접점, 공식확인, 구로 접근, 효과점수
- 연락상태, 미팅상태, 관리직·팀, 최근 연락일, 미팅일, 사용 시작자, 피드백 사용자, 메모
- 해당 거점의 위치·동선과 시나리오로 이동하는 버튼

설계파트너에는 기존 6주 사용·피드백 관리 기능을 유지한다.

### 3.3 계획·성과

- 기존 월간 캘린더와 날짜 상세 체크리스트
- 8~12월 월별 목표: 신규 대상, 관리직 미팅, 신규 사용, 누적 피드백 사용자, 이동 조건, 완료 기준, 판정
- 핵심 KPI와 남은 목표
- 주간 회고와 다음 결정
- 계획 수치와 실제 수치를 구분한다.

### 3.4 위치·동선

실제 지도 API를 넣지 않고 다음 네 단계로 구성한다.

1. **권역 위치 개요도:** 서울 서부·강남·수도권·충청·영남·호남·강원·제주에 80곳을 점으로 표시한다. 실제 축척이나 실시간 내비게이션 지도가 아니라는 문구를 표시한다.
2. **건물·클러스터:** 같은 건물에 있는 지점 수, 회사, 대표주소, 추천일, 운영 방식을 표시한다.
3. **일자별 방문 순서:** 출발지, 1번 방문, 2번 방문, 복귀 또는 다음 행동을 타임라인으로 표시한다.
4. **실제 지도 연결:** 각 주소에 주소 복사, 네이버지도 열기, 카카오맵 열기 버튼을 둔다. 외부 링크는 새 창으로 열고 `noopener`를 적용한다.

출발지는 편집 가능하며 기본값은 `구로`다. 실시간 이동시간을 계산하거나 확정값처럼 표시하지 않는다. 방문 순서는 거리보다 확정된 약속 시각을 우선하며, 약속이 없으면 운전부터 하지 않고 우선순위가 높은 거점에 전화하도록 안내한다.

기본 8월 순서는 다음과 같다.

- 8월 1주: 신도림테크노마트 → 신도림 디큐브시티 → 구로 G밸리
- 8월 2주: 교보생명 당산사옥 → 문래 세미콜론
- 8월 3주: 강서 송화쇼핑센터 → 마곡 NY타워 → 마곡 마커스빌딩
- 8월 4주: 상암 → 합정

전국 이동은 같은 권역에서 관리직 약속이 2건 이상 확정됐을 때만 실행한다.

### 3.5 영업 시나리오

기존 시나리오 전체를 유지하고 다음 분류로 탐색한다.

- 첫 연락·담당자 찾기
- 방문 약속·자료 전달
- 현장 관리직 설명
- 설계사 소개·첫 사용
- D7·D14·D30·D42 후속
- 거절·보류·내부 확인
- 권역 출장·재방문

시나리오는 별도 보관함에서 수정할 수 있으며, 오늘 실행 카드와 거점 행에서는 현재 단계에 맞는 시나리오를 바로 펼친다.

## 4. 데이터 설계

### 4.1 거점 원장

`targets`를 80개 공식 거점의 단일 원장으로 확장한다. 각 거점은 안정적인 고유 ID를 가진다.

필수 필드:

- 조사값: `rank`, `phase`, `week`, `region`, `cluster`, `sector`, `company`, `channel`, `branch`, `address`, `phone`
- 평가값: `managerImpact`, `plannerAccess`, `officialCertainty`, `guroAccess`, `effectScore`
- 실행값: `recommendedApproach`, `contactStatus`, `meetingStatus`, `managerTeam`, `lastContactAt`, `meetingAt`, `activeUsers`, `feedbackUsers`, `note`
- 근거값: `source`, `sourceCheckedAt`
- 기존 호환값: `position`, `name`, `contactRoute`, `status`, `nextActionAt`, `introducer`

거점 데이터는 한 곳에서만 수정한다. 우선 40, 위치·동선, 오늘 실행은 이 원장을 참조해 표시하며 별도 복사본을 만들지 않는다.

### 4.2 월별 목표와 동선

- `monthlyGoals`: 8월부터 12월까지 5개 목표 행
- `routeClusters`: 우선 40곳을 묶은 10개 건물 동선
- `selectionCriteria`: 평가 항목 4개와 가중치
- `sources`: 원수사·협회·대리점 조회 공식 출처와 확인일

모든 배열은 JSON 백업에 포함하고 불러오기 때 형식을 정리한다.

## 5. 기존 저장 데이터 이전

- 저장 키는 `inpa-sales-marketing-execution-v1`을 유지한다.
- 스키마 버전을 올리고 누락된 새 배열과 설정만 보충한다.
- 기존 대상이 빈 기본 행 한 개뿐이면 공식 80곳으로 교체한다.
- 사용자가 입력한 기존 대상이 있으면 삭제하지 않고 80곳 뒤에 보존한다.
- 이미 같은 고유 ID의 공식 거점이 있으면 사용자 실행값을 우선하고 조사값만 누락된 부분을 채운다.
- 새 설정 `activeTab`, `targetView`, `targetFilters`, `selectedCluster`, `origin`이 없으면 안전한 기본값을 넣는다.
- 저장값을 읽지 못하면 복구용 사본을 남기고 기본 계획을 연다.

## 6. 위치와 방문 시나리오 판정

- 약속 0건: 우선 거점에 전화하고 현장 출발을 권하지 않는다.
- 같은 건물 약속 1건: 해당 약속을 먼저 표시하고 주변 지점은 자료 전달 허락 확인 대상으로만 보여준다.
- 같은 건물 약속 2건 이상: 30분 간격 묶음 방문을 제안한다.
- 여러 건물 약속: 약속 시각을 우선해 정렬하고, 시각이 같거나 비어 있을 때만 기본 동선 순서를 사용한다.
- 지방 권역: 관리직 약속 2건 미만이면 원격 확인으로 전환한다.
- 방문 종료 후: 결과와 다음 행동일 또는 제외 이유 중 하나를 반드시 기록하도록 안내한다.

## 7. 빈 상태·오류·사용 안내

- 필터 결과 없음: 필터를 초기화하거나 전체 80곳을 보도록 안내한다.
- 오늘 방문 없음: 다음 우선 전화 대상과 가장 가까운 실행일을 보여준다.
- 주소 없음: 주소를 채우면 지도 버튼을 사용할 수 있다고 안내한다.
- 외부 지도 연결 실패: 주소 복사 기능은 계속 제공한다.
- 중복·누락 ID: 불러오기 과정에서 새 ID를 부여하고 화면은 계속 연다.
- 고객 이름·증권·건강정보를 거점 메모에 기록하지 않도록 한 곳에 짧게 안내한다.

## 8. 반응형·접근성

- 데스크톱은 탭과 넓은 표를 제공한다.
- 모바일은 탭을 가로 스크롤하고, 거점은 핵심 정보 카드와 상세 펼치기로 보여준다.
- 운전 중 조작을 유도하지 않고 주차 후 확인하도록 위치 탭에 안내한다.
- 모든 탭과 하위 보기는 키보드로 전환할 수 있고 `aria-selected`, `role=tab`, `role=tabpanel`을 사용한다.
- 44px 이상의 조작 영역, 보이는 포커스, 충분한 명암을 유지한다.
- 인쇄에서는 활성 탭과 핵심 표가 읽히며 편집 버튼은 숨긴다.

## 12. 관점별 검토와 결정

### 1차 독립 검토

- 사업·PM: 첫 화면의 80곳 전체 표보다 오늘 출발지, 첫 방문, 다음 방문과 20명 목표의 막힌 단계를 우선해야 한다.
- 보험영업: 관리직 방문 허락과 설계사 개인 후속 의사는 분리하고, 방문 후 다음 행동 또는 제외 이유가 남아야 한다.
- 마케팅·그로스: 모든 작업은 거점·설계파트너의 다음 행동일에서 오늘 화면으로 모이고, 시나리오는 현재 단계에서 바로 열려야 한다.
- UX·데이터·QA: 거점 데이터는 한 원장에서 관리하고 기존 브라우저 저장값을 이전해야 한다.

### 2차 반론과 보완

- 외부 지도 링크만으로는 80곳 전체 위치를 조망하기 어렵다는 반론을 수용해 오프라인 권역 개요도를 추가했다.
- 7개 메인 탭은 자료 탐색 부담이 크다는 반론을 수용해 5개 메인 탭과 하위 보기로 줄였다.
- 동선은 거리순보다 방문 허락과 약속 시각을 우선하도록 정했다.

### 3차 대안 채점

| 대안 | 목표 적합성 | 실행속도 | 오프라인 안정성 | 데이터 정합성 | 모바일 | 총점 |
|---|---:|---:|---:|---:|---:|---:|
| 기존 앵커 유지·표 추가 | 5 | 9 | 10 | 6 | 5 | 35/50 |
| **5개 탭·개요도·외부 지도** | **9** | **8** | **9** | **9** | **9** | **44/50** |
| 7개 탭·실제 지도 API | 10 | 5 | 3 | 8 | 7 | 33/50 |

최종 결정은 `5개 메인 탭 + 오프라인 권역 개요도 + 건물별 동선 + 외부 지도 연결`이다.
