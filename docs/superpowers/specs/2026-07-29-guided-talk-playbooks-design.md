# 현대화 실전 화법 플레이북 설계

## 1. 목표

설계사가 소개 고객과 통화하거나 처음 대면할 때 다음 문장을 찾느라 긴 원고를 훑지 않도록, 현재 장면에 맞는 한 단계 카드와 고객 반응별 대응을 제공한다. 기존 빠른 문구 30개와 개인 화법은 그대로 유지한다.

## 2. 화면 구조

### 상위 모드

- `실전 상담`: 기본 진입. 두 플레이북을 고르고 단계별로 진행한다.
- `빠른 문구`: 기존 기본 30개, 개인 화법 CRUD, 숨김·복구, 공유 기능을 행동 변화 없이 유지한다.
- URL은 `mode=guided|quick`, `playbook=<key>`, `customerId=<number>`만 사용한다. 기존 `customer=<name>`은 읽기 호환만 유지하고 새 링크에서는 만들지 않는다.

### 실전 상담 홈

1. `소개받은 고객 첫 통화`
   - 시작 조건: 소개 경위를 사실대로 설명할 수 있을 때
   - 목표: 고객이 원하는 상담 방식과 다음 일정을 정한다.
2. `첫 대면 보장 점검`
   - 시작 조건: 상담 목적과 예상 시간을 먼저 설명할 때
   - 목표: 확인할 자료와 다음 상담 행동을 정한다.

### 플레이북 화면

- 데스크톱: 왼쪽 단계 목록, 가운데 현재 단계 카드, 오른쪽 고객 반응.
- 모바일: 상단 가로 단계 목록, 현재 카드, 고객 반응 펼침 영역, 이전·다음 버튼.
- 단계는 자유롭게 이동할 수 있고 완료를 강제하거나 서버에 진행상태를 저장하지 않는다.
- 진행 표시는 `현재 3/7`처럼 화면 안에서만 유지한다.

## 3. 데이터 구조

`lib/guided-talk-playbooks.ts`를 버전이 있는 정적 원본으로 둔다.

```ts
interface GuidedTalkPlaybook {
  key: string;
  title: string;
  description: string;
  durationLabel: string;
  goal: string;
  steps: GuidedTalkStep[];
  objectionKeys: string[];
  nextActions: GuidedTalkAction[];
}

interface GuidedTalkStep {
  key: string;
  title: string;
  goal: string;
  spokenText: string;
  questions: string[];
  checklist: string[];
  objectionKeys: string[];
  requiresSalesDisclosure?: boolean;
}

interface GuidedTalkObjection {
  key: string;
  label: string;
  responseText: string;
  secondRefusalText: string;
  terminal?: boolean;
}
```

- `spokenText`만 복사한다. 목표, 질문 설명, 확인할 점, 메모는 복사하지 않는다.
- 기존 `{고객명}`, `{설계사명}`, `{소속}`, `{직책}`, `{소속직책}`을 재사용하고 `{소개자명}`을 화면 로컬 변수로 추가한다.
- 모든 키는 영문 소문자와 하이픈으로 고정하고 버전 상수를 둔다.
- 단계 번호는 배열 순서에서 계산하며 본문에 저장하지 않는다.

## 4. 플레이북 내용

### 소개받은 고객 첫 통화

1. 신분·보험 상담 목적·통화 허락
2. 소개 경위 설명
3. 고객이 먼저 확인하고 싶은 항목
4. 실제 자료 기준 점검 방식
5. 상담 방식과 일정 선택
6. 약속 내용 확인 또는 통화 종료

주요 반응:

- 지금 바쁨
- 지금은 관심 적음
- 기존 담당 설계사 있음
- 소개 경위·개인정보가 궁금함
- 다시 연락받고 싶음
- 다음 연락을 원치 않음

### 첫 대면 보장 점검

1. 인사·신분 재확인
2. 오늘 상담 목적·예상 시간 합의
3. 고객이 먼저 확인하고 싶은 부분
4. 필요한 범위의 생활 변화 확인
5. 현재 보험·월 보험료·납입기간 확인
6. 실제 증권에서 보장과 지급 제한 확인
7. 고객 본인 동의와 자료 등록 안내
8. 오늘 확인한 내용 정리와 다음 일정

주요 반응:

- 증권이 없음
- 자료 공유가 걱정됨
- 보험료 부담이 걱정됨
- 기존 담당 설계사 있음
- 더 생각하고 싶음
- 오늘은 결정을 원치 않음

## 5. 문구 원칙

- 신분과 보험 상담·안내 목적을 숨기지 않는다.
- 고객이 말한 사실과 실제 증권에서 확인한 사실을 구분한다.
- 상품 변경이나 가입을 미리 결론내리지 않는다.
- 닫힌 선택지는 두 개의 진행 선택지와 종료 선택지를 함께 제공한다.
- 첫 거절 뒤 한 번만 범위를 줄이고, 재거절 또는 연락 중단 요청에는 추가 제안 없이 마친다.
- 결혼·자녀·주소는 필요한 이유를 설명하고 질문 허락을 받은 경우에만 선택적으로 묻는다.
- 회사 실적·수상·점유율, 특정 상품명, 오래된 통계, 보장·보험금·절감 단정, 공포·차별 표현을 넣지 않는다.

## 6. 고객 정보와 URL

- 고객 상세와 오늘 전화할 고객은 `/scripts?customerId=<id>`로 연결한다.
- `/scripts`는 `getCustomer(id)`로 소유자 범위 고객 이름만 불러온다.
- 조회가 끊기면 기본 플레이북은 계속 쓰고 이름을 직접 입력할 수 있다.
- 고객이 입력을 시작한 뒤 늦게 온 조회 응답이 입력값을 덮어쓰지 않는다.
- 소개자 이름은 화면 상태로만 유지하며 URL, 서버, 분석 이벤트에 넣지 않는다.

## 7. 행동과 계측

- 플레이북 열기, 단계 보기, 고객 반응 열기, 다음 행동 클릭을 제품 계측에 남긴다.
- 속성은 `playbook_key`, `step_key`, `branch_key`, `action_key`, `version`의 정해진 값만 사용한다.
- 고객 ID, 고객·소개자 이름, 전화번호, 대화문, 답변 원문은 계측하지 않는다.
- 계측 실패는 화면 동작을 막지 않는다.

다음 행동:

- 첫 통화: 일정 열기, 예약 안내 빠른 문구 열기, 연락 종료.
- 대면 상담: 선택 고객의 분석 탭 열기, 일정 열기, 결과 공유 빠른 문구 열기.
- 고객 ID가 없으면 고객 목록으로 연결해 대상을 먼저 고르게 한다.

## 8. 상태와 접근성

- 데이터는 정적이므로 별도 로딩 상태가 없다.
- 고객·프로필·개인 화법 연결 실패는 각각 독립적으로 표시하며 기본 플레이북은 계속 사용한다.
- 단계 버튼에 `aria-current="step"`을 사용한다.
- 고객 반응 버튼은 `aria-expanded`와 `aria-controls`를 사용한다.
- 반응을 열면 응답 영역 제목으로 포커스를 옮기고 닫으면 원래 버튼으로 돌려준다.
- 360px에서도 가로 본문 스크롤이 없어야 하며 모든 버튼은 최소 44px 높이를 갖는다.
- 모션 감소 설정에서는 불필요한 전환을 사용하지 않는다.

## 9. 테스트 기준

- 플레이북 버전·키 고유, 단계 번호 연속, 분기 참조 고아 0.
- 각 플레이북 첫 단계가 신분·소속·보험 상담 목적·대화 허락을 포함한다.
- 발화문 복사 결과에 코치용 문구가 포함되지 않는다.
- 연락 중단 분기와 재거절 문장은 추가 제안 없이 끝난다.
- 위험 문구 정규식 0건.
- 모든 변수가 비어 있거나 채워져도 토큰, 이중 공백, 깨진 조사가 남지 않는다.
- `customerId` 조회 성공·404·늦은 응답·직접 입력 경합을 검증한다.
- 단계 이동, 분기 열기·닫기, 마지막 행동, 키보드 포커스를 검증한다.
- 기존 30개, 개인 CRUD, 숨김·복구, 공유 테스트가 그대로 통과한다.
- 360px·390px·768px·1440px 실브라우저 렌더를 확인한다.

## 10. 제외 범위

- 설계사 영입 플레이북
- 플레이북 전체 복제·개인화와 임의 분기 편집
- 고객 답변 저장
- 서버 진행상태 저장
- AI 실시간 추천
- 새 DB 테이블 또는 마이그레이션
