# 정기결제·달력 개월 쿠폰 페르소나 회의록

- 일자: 2026-07-26
- 의사결정 범위: 카드 등록형 1~3개월 쿠폰, 달력 날짜 기준 정기결제, 무료 전환 안내, 고객 데이터 보존
- 상태: 3차 토론 완료, 조건부 승인
- 연결 설계: `2026-07-26-recurring-billing-calendar-coupon-design.md`

## 1. 회의 질문

1. 쿠폰을 쓴 회원도 카드 등록을 필수로 해야 하는가?
2. “1개월”을 30일이 아니라 달력 날짜로 계산하려면 어떤 규칙이 필요한가?
3. 무료 기간이 끝난 뒤 자동 결제로 전환할 때 무엇을 다시 확인해야 하는가?
4. 결제 실패나 결과 미확정 상태에서 중복 결제와 부당한 이용 중단을 어떻게 막는가?
5. 유료 요금제가 끝나도 고객·메모·AI 요약 데이터에 계속 접근할 수 있어야 하는가?

## 3. 1차 토론: 전환율 대 신뢰

### 공격

- 카드만 등록하면 무료 종료 후 곧바로 자동 결제하는 방식은 전환율에는 유리하지만, 사용자가 날짜와 금액을 기억하지 못하면 기습 결제로 받아들일 수 있다.
- 쿠폰을 받는 순간부터 유료 동의를 묶으면 1~3개월 뒤 결제에 대한 별도 인식이 약해진다.
- 기존 고객 데이터까지 잠그면 단기 재결제는 늘 수 있어도 이탈·민원·브랜드 손상이 커진다.

### 방어

- 카드 등록 자체는 무료 체험 악용 방지와 결제 준비에 필요하다.
- 결제 예정일과 금액을 체험 시작 화면, 요금제 화면, 사전 알림에 반복해 보여주면 예측 가능성을 높일 수 있다.
- 기존 데이터는 보존하되 새 녹음·AI 요약·고급 자동화를 유료 가치로 두면 강압 없이 재결제를 유도할 수 있다.

### 1차 결론

- 카드 등록은 필수로 유지한다.
- 카드 등록 동의와 첫 유료 결제 재확인은 분리한다.
- 무료 전환 시 기존 고객·메모·요약 접근을 막지 않는다.

## 4. 2차 토론: 단순 구독 행 대 별도 결제 원장

### 공격

- 기존 `Subscription`에 다음 결제일과 상태만 추가하면 빠르지만, 승인 결과 미확정·중복 방지·환불·웹훅 재처리를 증명하기 어렵다.
- KICC 요청이 시간초과됐다고 다시 승인 요청을 보내면 실제로는 첫 요청도 승인되어 중복 결제가 될 수 있다.
- 쿠폰을 먼저 사용 처리하고 카드 등록 콜백이 늦게 오면 혜택과 결제 동의 상태가 갈라질 수 있다.

### 방어

- 이용 권한과 금전 거래를 별도 원장으로 만들면 복잡도는 늘지만, 운영자가 각 사건을 복원할 수 있다.
- 인파 내부의 영구 결제 주기 키로 중복을 막고, 결제 결과 미확정은 KICC 거래 조회로만 확정한다.
- 쿠폰은 짧은 점유 상태를 먼저 만들고 카드 등록 완료 후 원자적으로 사용 확정한다.

### 2차 결론

- **2안, 별도 결제 원장 구조**를 채택한다.
- `Subscription`은 현재 이용 권한을 보여주는 결과값으로 유지한다.
- 결제 동의, 결제수단 키, 주문, 시도, 웹훅, 안내 이벤트를 분리한다.

## 5. 3차 토론: 운영 가능성과 출시 조건

### 공격

- 법적 문구, KICC 상점 심사, 샌드박스 취소, 실정산 확인 없이 자동 결제를 켜면 기술적으로 동작해도 운영 출시로 볼 수 없다.
- `FREE_TIER_UNLIMITED=True`인 현재 상태에서는 유료 전환 후 얻는 실제 차이가 불명확하다.
- 미확정 결제에 무제한 임시 이용을 주거나 바로 무료로 내리면 각각 비용 누수와 고객 피해가 생긴다.

### 방어

- 카드 등록, 정기 승인, 웹훅·대사 기능을 별도 기본 닫힘 게이트로 나누면 단계별 검증이 가능하다.
- 미확정 상태에는 최대 24시간 임시 이용과 운영 알림을 두고, 재승인 대신 상태 조회를 수행한다.
- 무료 요금제의 새 녹음·AI 요약 한도를 별도로 확정한 뒤에만 실제 유료 전환을 연다.

### 3차 결론

- 구현 완료와 운영 결제 개방을 분리한다.
- KICC 심사·샌드박스·법적 문구·환불·PostgreSQL 동시성·실정산 검증이 끝나기 전에는 자동 결제를 열지 않는다.
- 원본 녹음 7일 삭제와 기존 고객 기록 접근은 요금제와 무관한 원칙으로 둔다.

## 7. 채택·보류·기각

### 채택

- 일반 쿠폰은 1~3 달력 개월로 제한
- 쿠폰 사용 전 카드 등록 필수
- 무료 시작 동의와 첫 유료 결제 재확인 분리
- 최초 활성화 날짜를 기준으로 월말 보정
- 결제 원장과 이용 권한 분리
- 명시적 실패와 결과 미확정 분리
- 무료 전환 안내는 결제 사건별 1회 노출
- 기존 고객·메모·AI 요약 데이터 계속 접근
- 원본 녹음은 모든 요금제에서 7일 안에 삭제

### 보류

- 연간 자동 결제: 월 결제 안정화 이후
- 쿠폰 양도·선물: 악용 방지와 CS 정책을 별도로 설계한 뒤
- 고객 데이터 전체 내보내기 확장: 기존 기능 확인 후 별도 범위로 계획

### 기각

- 30일을 1개월로 계산
- 결제 시간초과 시 즉시 재승인
- 쿠폰 악용 추적을 위한 카드 지문·전화번호·이메일의 계정 간 결합
- 무료 전환 시 기존 고객 기록을 잠가 재결제를 유도하는 방식

## 8. 최종 권고

인파의 재결제 이유는 “데이터를 잃을까 봐”가 아니라 “쌓인 고객 이력 위에서 새 상담을 더 빠르고 정확하게 이어가기 위해서”여야 한다. 따라서 기존 기록은 신뢰 자산으로 보존하고, 유료 요금제는 새 녹음, AI 요약, 자동 후속 관리처럼 계속 발생하는 업무 비용을 줄이는 데 가치를 둔다.
