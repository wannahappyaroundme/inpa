# 여러 증권 비교, 양쪽 중복 선택 UX 설계

**작성일:** 2026-07-27  
**상태:** 사용자 최종 승인, 상세 구현 계획 작성 완료, 구현 전

**구현 계획:** `docs/superpowers/plans/2026-07-27-release-3-multi-policy-overlap-selection.md`

## 1. 사용자가 원하는 비교

고객이 가진 기존 증권 A1, A2, A3 중 A3만 새 증권 B1으로 바꾸어 구성 차이를 보려면 다음 비교가 가능해야 한다.

```text
왼쪽 구성: A1 + A2 + A3
오른쪽 구성: A1 + A2 + B1
```

A1과 A2는 동일한 실제 증권이며 양쪽에 동시에 포함된다.

## 2. 현재 원인

- 백엔드 `side_a_ids`와 `side_b_ids`는 같은 보험 ID를 양쪽에서 처리할 수 있다.
- 백엔드 회귀 테스트도 동일 ID를 양쪽에 넣는 사례를 이미 포함한다.
- 프런트는 증권마다 `SideAssign = "A" | "B" | "none"` 하나만 저장해 양쪽 포함이 구조적으로 불가능하다.
- 한쪽이 비어 API가 400을 반환하면 비교 선택 UI 전체가 오류 카드로 교체되어 사용자가 선택을 고칠 수 없다.
- `비교 묶음 A/B` 태그는 DB의 `portfolio_type`과 이번 비교의 선택 상태를 혼동시킨다.

## 3. 목표

1. 고객의 분석 가능한 모든 증권을 카드 목록으로 보여준다.
2. 한 증권을 왼쪽, 오른쪽, 양쪽 또는 어느 쪽에도 포함하지 않을 수 있다.
3. 선택 UI는 로딩·비교 오류·한도 오류가 나도 사라지지 않는다.
4. 사용자가 확정한 선택으로만 비교를 실행한다.
5. 선택이 변경되면 이전 결과가 최신인 것처럼 복사되지 않는다.
6. 화면 용어를 `왼쪽 구성 / 오른쪽 구성`으로 통일한다.

## 4. 선택한 UX

### 4.1 단일 카드 목록과 독립 선택

각 증권 카드에는 서로 독립적인 두 컨트롤을 둔다.

- `왼쪽에 포함`
- `오른쪽에 포함`

둘 다 선택할 수 있다. 둘 다 선택된 카드는 `양쪽 포함` 상태가 카드에서 명확히 보인다.

카드에는 다음 사실 정보만 표시한다.

- 보험사·증권명
- 계약자·피보험자
- 월 보험료
- 계약 기간
- 분석 포함/확인 필요 상태

`비교 묶음 A`, `비교 묶음 B` 태그는 제거한다.

### 4.2 선택 상태

프런트 상태는 증권별 독립 boolean을 보관한다.

```text
Record<insuranceId, { left: boolean; right: boolean }>
```

배열은 비교 실행 시점에만 만든다.

```text
side_a_ids = left=true인 보험 ID
side_b_ids = right=true인 보험 ID
```

내부 API 키는 하위호환을 위해 유지하며 화면에는 노출하지 않는다.

### 4.3 초기 선택

새로 불러온 분석 가능 증권은 DB 분류를 초기 프리셋에만 사용한다.

| 증권 저장 분류 | 왼쪽 | 오른쪽 |
|---|---:|---:|
| 현재 등록 증권 `portfolio_type=1` | 선택 | 선택 |
| 비교 화면에서 추가한 증권 `portfolio_type=2` | 미선택 | 선택 |
| 템플릿·기타 | 미선택 | 미선택 |
| 취소·검토 전·분석 제외 | 선택 불가 | 선택 불가 |

목록 새로고침 시 기존 사용자의 left/right 선택을 보존한다. 새로 들어온 ID에만 초기 프리셋을 적용한다.

이 프리셋에서 사용자는 오른쪽의 A3만 해제하면 즉시 `A1+A2+A3` 대 `A1+A2+B1` 비교를 만들 수 있다.

### 4.4 구성 요약과 실행

카드 목록 위에 두 요약을 둔다.

- `왼쪽 구성 N개`
- `오른쪽 구성 N개`

선택한 증권 이름을 chip 또는 줄바꿈 목록으로 보여주고, 모바일에서는 개수와 축약 목록을 사용한다.

비교는 `선택한 구성 비교하기` 버튼으로 실행한다. 토글을 누를 때마다 자동 요청하지 않는다.

이유:

- 여러 장을 연속 선택할 때 결과가 흔들리지 않는다.
- 추후 AI 비교 gate가 열려도 선택 동작마다 사용량이 차감되는 위험을 막는다.
- 어떤 선택으로 만든 결과인지 사용자가 인지할 수 있다.

## 5. 결과와 상태

### 5.1 결과 라벨

모든 렌더링과 복사 문구에서 다음을 사용한다.

- `왼쪽 구성`
- `오른쪽 구성`

`증권 A/B`, `비교 묶음 A/B`는 사용자 화면에서 제거한다. API response의 `current/proposed` 호환 키는 변경하지 않는다.

### 5.2 유효성

| 상태 | 동작 |
|---|---|
| 한쪽 0개 | API 호출 없음, 필요한 쪽에 증권을 고르는 다음 행동 안내 |
| 양쪽 구성이 완전히 같음 | API 호출 없음, 오른쪽 구성을 조정하면 차이를 볼 수 있다는 안내 |
| 양쪽 1개 이상이며 다름 | 비교 버튼 활성 |
| 비교 중 | 선택 UI 유지, 결과 영역만 loading |
| 비교 실패 | 선택 유지, 결과 영역에 다시 비교 |
| 402 | 선택 유지, 한도 안내 modal |

### 5.3 오래된 결과 차단

- 마지막 성공 요청의 left/right ID snapshot을 저장한다.
- 현재 선택이 snapshot과 다르면 결과를 `선택 변경됨` 상태로 표시한다.
- 이 상태에서는 결과 복사 버튼을 비활성화한다.
- 다시 비교 성공 후에만 복사를 연다.
- 느린 과거 응답이 최신 결과를 덮지 않도록 기존 request generation guard를 유지한다.

## 6. 접근성·모바일

- 각 독립 선택은 `button aria-pressed` 또는 checkbox로 명확한 이름을 가진다.
- 키보드만으로 왼쪽·오른쪽을 각각 선택할 수 있다.
- 색상 외에 텍스트·아이콘·pressed 상태로 선택을 구분한다.
- 모바일 카드에서도 버튼 최소 높이 44px을 지킨다.
- 비교 CTA는 모바일에서 카드 목록 아래 쉽게 찾을 수 있게 둔다.
- 오류와 loading은 `role=status`·`role=alert`를 상태에 맞게 사용한다.

## 7. 테스트

### 7.1 프런트

- 한 카드에서 왼쪽과 오른쪽을 동시에 선택
- 같은 ID가 두 요청 배열에 모두 포함
- 기존 3개 + 추가 1개의 초기 프리셋
- 오른쪽에서 A3 해제 후 정확한 배열 전송
- 한쪽 빈 상태와 동일 구성에서 API 호출 0회
- 비교 오류 후 카드와 선택 유지
- 선택 변경 후 이전 결과 복사 차단
- 새 증권 refresh 시 기존 선택 보존
- 취소·검토 전 증권의 선택 차단과 다음 행동
- 모바일·키보드·accessible name 검증

### 7.2 백엔드

- 동일 보험 ID가 양쪽에 있을 때 각 side에서 정확히 한 번 집계
- `A1+A2+A3` 대 `A1+A2+B1` 월 보험료·담보 합계 정확성
- 다른 고객·소유자·분석 불가 ID의 기존 차단 유지

### 7.3 브라우저

- 실제 고객 상세의 `여러 증권 비교` 탭에서 카드 4개 확인
- 독립 선택, 비교 실행, 표·차트·복사 문구를 확인
- 좁은 모바일 viewport에서 가로 넘침 없음
- API 실패를 주입해 선택 UI가 유지되는지 확인

## 8. 변경 경계

- DB migration 없음
- 백엔드 API shape 변경 없음
- 비교 계산·중립성·권유 금지 규칙 변경 없음
- 프런트 선택 상태, 카드 UI, 결과 라벨, 오류 배치와 회귀 테스트만 변경
