# 상담 AI 요약 내부 비교 설계

작성일: 2026-07-27  
상태: 구현 승인  
대상: 인파 관리자 내부 검토자

## 1. 결정

운영 상담 녹음 기능과 분리된 관리자 전용 비교 화면을 만든다.

하나의 가상 상담 음성을 OpenAI 음성 전사 API로 한 번만 글로 바꾼 뒤,
개인정보 형태를 가린 동일 전사문과 동일한 지시문, 동일한 JSON 출력
형식을 ChatGPT와 Claude에 각각 한 번 전달한다. 결과는 모델명을 가린
`결과 A`와 `결과 B`로 나란히 보여주고, 평가를 마친 뒤 모델명을
확인한다.

이번 실험이 답하는 질문은 다음 하나다.

> 같은 상담 전사문을 어느 요약 모델이 더 정확하고 실무적으로
> 정리하는가?

이번 실험은 음성 인식 공급자 비교, 실제 고객 대상 공개, 고객 메모
저장, 요금제와 사용량 차감을 다루지 않는다.

## 2. 배경과 확인된 제약

- 기존 운영 코드에는 Cloudflare R2 기반 상담 녹음, 한 녹음당 AI 요약
  한 번, 편집 가능한 다중 메모, 비용 상한, 파일럿 권한, 자동삭제
  구조가 배포되어 있다.
- 운영 녹음과 AI 요약 환경 스위치는 기본적으로 닫혀 있다.
- 기존 `ANTHROPIC_API_KEY`는 보장분석에 사용 중이다. 비교 실험은 같은
  키를 사용하되 보장분석 모델 설정과 별도의 모델 환경변수를 사용한다.
- `OPENAI_API_KEY`는 Render의 `inpa-be` 비밀 환경변수로 등록되었다.
- OpenAI Transcriptions API는 한국어와 `webm`을 지원하며, 파일 업로드는
  최대 25MB다. `gpt-4o-transcribe-diarize`는 화자 구분 결과를 제공하고
  30초를 넘는 파일에는 `chunking_strategy="auto"`가 필요하다.
- 2026-07-27 현재 공개 Claude API 문서는 오디오 입력을 지원하지 않는다고
  명시한다. Claude 앱의 음성 모드와 인파 서버가 사용하는 Claude
  Messages API는 별도 제품 표면이다.
- 공급자 지원은 바뀔 수 있으므로 비교 코드가 Claude의 오디오 미지원을
  영구 가정하지는 않는다. 이번 실험은 전사와 요약을 분리한 공통
  인터페이스를 사용한다.

## 3. 검토한 접근

| 접근 | 장점 | 단점 | 결정 |
|---|---|---|---|
| API 연결 명령만 한 번 실행 | 구현이 가장 작다 | PM이 결과를 반복해서 비교하기 어렵다 | 제외 |
| 관리자 전용 짧은 음성 A/B 비교 | 기존 운영에 영향 없이 품질과 비용을 직접 확인할 수 있다 | 짧은 요청만 허용하며 결과가 새로고침 후 사라진다 | 채택 |
| 운영 녹음에 두 모델을 동시에 연결 | 실제 환경을 바로 검증한다 | 고객 데이터, 동의, 비용, 메모 한 번 규칙이 한꺼번에 바뀐다 | 이후 별도 설계 |

## 4. 범위

### 포함

- 관리자 전용 `/admin/consultations/compare`
- 한 번에 가상 상담 음성 한 파일 업로드
- 최대 5분, 최대 25MB, OpenAI가 지원하는 오디오 형식만 허용
- OpenAI 화자 구분 전사 한 번
- 기존 개인정보 형태 가림 로직 적용
- 동일한 전사문으로 ChatGPT와 Claude 요약을 병렬로 각 한 번 호출
- 두 결과를 무작위 A/B 순서로 표시
- 공통 전사문 접기·펼치기
- 네 가지 고정 요약 구역
- 처리시간, 입력·출력 토큰, 공급자 결과 상태 표시
- 사람이 표시하는 오류 체크와 A/B 선택
- 평가 후 모델명과 실제 모델 ID 공개
- 모바일과 데스크톱의 로딩, 부분 실패, 전체 실패, 빈 상태

### 제외

- 실제 고객 음성
- 고객, 고객 메모, 녹음, 무료 사용권, 요금제, 결제와 연결
- 비교 결과, 원음, 전사문, 요약문, 평가 내용을 DB나 R2에 저장
- 결과 다운로드와 공유
- 비교 결과를 근거로 한 외부 홍보 문구
- Claude 앱 자동화 또는 소비자 구독 사용
- 운영 녹음·AI 요약 스위치 활성화
- 공급자 자동 선정과 실제 서비스 기본 모델 변경

## 5. 사용자 흐름

1. 관리자가 `상담 AI 비교` 화면에 들어간다.
2. 화면은 `가상 상담 음성만 사용해 주세요`와 `내부 검토용`을 표시한다.
3. 관리자가 파일을 선택하고 `실제 고객 정보가 없는 가상 녹음입니다`를
   확인한다.
4. 프론트엔드는 형식과 25MB 제한을 먼저 검사한다.
5. 관리자가 `비교 시작`을 누른다. 같은 파일은 실행 중 다시 제출할 수
   없다.
6. 백엔드는 관리자 권한, 환경 스위치, 확인값, 형식, 크기, 길이를 다시
   검사한다.
7. 백엔드는 OpenAI에 원음을 한 번 전달해 화자 구분 전사문을 받는다.
8. 백엔드는 전사문의 개인정보 형태를 가린다.
9. 백엔드는 동일한 가림 전사문, 동일한 지시문과 JSON 형식을 ChatGPT와
   Claude에 병렬로 한 번씩 전달한다.
10. 한 공급자가 실패해도 다른 공급자 결과는 보여준다.
11. 프론트엔드는 모델명을 숨긴 `결과 A`, `결과 B`를 보여준다.
12. 관리자는 사실성, 누락, 화자 구분, 만든 내용과 다음 행동을 평가한다.
13. `모델명 보기`를 누르면 공급자, 모델 ID, 처리시간과 토큰을 공개한다.
14. 새로고침하거나 화면을 나가면 원음과 비교 내용은 사라진다.

## 6. 화면 설계

### 상단

- 제목: `상담 AI 비교`
- 보조 문구: `가상 상담으로 요약 결과를 나란히 확인합니다.`
- 상태 칩: `내부 검토용`

### 입력 카드

- 파일 선택
- 파일명, 크기, 지원 여부
- 확인 선택: `실제 고객 정보가 없는 가상 녹음입니다`
- 기본 버튼: `비교 시작`
- 안내: `이 화면의 음성과 결과는 고객 메모에 저장되지 않습니다.`

### 처리 상태

- `음성을 글로 바꾸고 있어요`
- `두 가지 요약을 만들고 있어요`
- 오래 걸릴 때: `결과를 정리하고 있어요. 화면을 그대로 두면 이어집니다.`
- 실패한 단계와 다시 할 수 있는 다음 행동을 쉬운 말로 표시

### 결과

- 공통 전사문은 기본 접힘
- 두 열의 `결과 A`, `결과 B`
- 모바일은 A 다음 B의 세로 배치
- 각 결과는 아래 네 구역만 표시
  - 상담 핵심
  - 고객이 중요하게 본 내용
  - 확인할 내용
  - 다음 할 일
- 평가 선택
  - 빠진 내용
  - 대화에 없는데 만든 내용
  - 금액·날짜 오류
  - 화자 구분 오류
  - 바로 메모로 사용할 수 있음
- 최종 선택
  - A 우세
  - B 우세
  - 동률
  - 판단 보류
- `모델명 보기` 이후 공급자, 모델 ID, 처리시간, 토큰 표시

## 7. 서버 설계

### 환경 설정

모든 모델 ID는 환경변수로 주입하고 코드에 고정하지 않는다.

```text
CONSULTATION_AI_COMPARISON_ENABLED=False
OPENAI_API_KEY=<secret>
OPENAI_TRANSCRIPTION_MODEL=<model-id>
OPENAI_COMPARISON_MODEL=<model-id>
ANTHROPIC_COMPARISON_MODEL=<model-id>
CONSULTATION_COMPARISON_MAX_BYTES=26214400
CONSULTATION_COMPARISON_MAX_DURATION_SECONDS=300
```

비교 환경 스위치는 기본적으로 닫는다. 로컬·미리보기 실험과 PM의 운영
승인 전에는 운영에서 열지 않는다.

### API

```text
POST /api/v1/admin/consultations/comparison/
Content-Type: multipart/form-data
```

요청:

```text
audio=<binary>
synthetic_confirmed=true
```

응답 개념:

```json
{
  "transcript": {
    "segments": [
      {"speaker": "화자 1", "text": "가림 처리된 전사문"}
    ]
  },
  "results": [
    {
      "slot": "A",
      "provider": "openai",
      "model": "environment-injected-model",
      "status": "success",
      "summary": {
        "consultation_core": [],
        "customer_priorities": [],
        "items_to_confirm": [],
        "next_actions": []
      },
      "latency_ms": 0,
      "input_tokens": 0,
      "output_tokens": 0,
      "error_code": ""
    }
  ]
}
```

응답의 공급자 순서는 서버가 매 요청 무작위로 정한다. 공급자와 모델
정보는 관리자 브라우저에만 전달되며, 화면은 사용자가 공개하기 전까지
가린다. 개발자 도구까지 막는 완전한 블라인드는 이번 범위가 아니다.

### 공급자 경계

- `TranscriptionProvider`: 오디오를 화자 구분 전사 세그먼트로 변환
- `SummaryProvider`: 가림 전사문과 공통 스키마를 구조화 요약으로 변환
- OpenAI와 Anthropic 구현은 각각 자기 SDK와 오류 체계를 감싼다.
- 기존 운영 `ClovaSpeechProvider`와
  `AnthropicConsultationSummarizer`의 설정과 동작은 변경하지 않는다.
- 비교용 Claude 모델은 보장분석·운영 상담 요약 모델 환경변수와 분리한다.

### 공정성

- OpenAI 전사 결과를 한 번만 만든다.
- 전사 후 같은 문자열을 두 요약 공급자에 전달한다.
- 같은 시스템 목표, 금지 규칙, 네 구역, 글자·항목 제한을 사용한다.
- 각 공급자는 네 구역의 동일 JSON 스키마를 만족해야 한다.
- 요약 내용이 마음에 들지 않는다는 이유로 자동 재요약하지 않는다.
- 구문 오류처럼 결과를 사용할 수 없는 경우도 해당 모델의 실패로
  표시한다.

## 8. 개인정보와 보안

- API 키는 Render 백엔드 비밀 환경변수에서만 읽는다.
- 키를 브라우저, Vercel 공개 변수, 응답, 로그에 노출하지 않는다.
- 관리자 인증은 기존 `IsAdmin` 권한을 서버에서 확인한다.
- 일반 설계사와 비로그인 사용자는 403 또는 401을 받는다.
- 백엔드는 파일명, 음성 내용, 전사문, 요약문을 일반 로그에 남기지 않는다.
- 오류 로그에는 예외 종류, 단계, 크기, 처리시간과 결과 코드만 남긴다.
- 요청 처리 중 생긴 임시 파일은 성공·실패와 관계없이 `finally`에서
  삭제한다.
- 이번 화면은 R2와 DB에 콘텐츠를 저장하지 않는다.
- 실제 고객 음성 사용은 UI 확인만으로 허용하지 않는다. 실제 고객
  파일럿은 공급자별 국외이전, 녹음, 민감정보 동의와 삭제 검증을 포함한
  별도 운영 승인 후 진행한다.
- 공급자 응답 저장 옵션은 끈다. 요청 ID는 장애 조사에 필요한 경우에만
  콘텐츠와 분리해 남긴다.

## 9. 오류와 재시도

- 파일 형식, 크기, 길이, 확인값 오류는 외부 API를 호출하지 않는다.
- 인증·권한·잘못된 요청은 재시도하지 않는다.
- 연결이 성립하지 않은 것이 명확한 네트워크 오류만 1초, 2초, 4초 간격으로
  최대 세 번 시도할 수 있다.
- 요청이 공급자에게 접수됐는지 알 수 없는 시간초과는 자동으로 다시
  제출하지 않고 해당 공급자를 `확인 필요` 상태로 표시한다.
- 한 요약 공급자가 실패해도 성공한 다른 결과와 공통 전사문은 보여준다.
- 전사 실패 시 두 요약 공급자는 호출하지 않는다.
- 프론트엔드는 중복 클릭을 막고, 실패 후 사용자가 새 요청을 명시적으로
  시작할 수 있게 한다.

## 10. 품질 평가

### 초기 연결 확인

- 3~5분 가상 상담 한 건
- 전사 한 건과 두 요약이 유효한 JSON으로 완료
- 모델별 호출 수 한 번
- 키와 콘텐츠 로그 노출 없음
- 임시 파일 부재 확인

### 후보 비교

연결 확인 후 5개의 3~5분 가상 상담으로 확대한다. 이번 동기식 내부
비교 화면에서는 5분 상한을 유지하고, 더 긴 녹음은 운영 비동기 구조를
검증할 때 별도로 다룬다.

1. 조용한 환경의 단순 상담
2. 두 화자의 발언이 자주 교차하는 상담
3. 보험료, 보장금액과 날짜가 많이 등장하는 상담
4. 고객이 확답하지 않고 고민과 부정을 표현하는 상담
5. 잡음과 불완전한 문장이 있는 상담

각 음성은 실행 전에 사람이 다음 정답표를 만든다.

- 확정된 사실
- 고객 요구와 우려
- 설계사가 설명한 내용
- 결정된 사항
- 다음 행동과 담당자
- 말하지 않은 사항

### 채점

| 기준 | 비중 | 치명적 오류 |
|---|---:|---|
| 사실성 | 25% | 보험료, 보장금액, 보험사, 날짜 등 핵심 사실 생성·변경 |
| 핵심 누락 | 20% | 고객 결정, 중요 우려, 확정 약속 누락 |
| 화자 구분 | 15% | 고객 의견을 설계사 권유로 뒤바꿈 |
| 개인정보 | 10% | 가림 정보를 복원하거나 새로운 개인정보 추론 |
| 다음 행동 | 10% | 대화에 없는 행동·담당자·기한 생성 |
| 편집량 | 10% | 대부분 다시 작성해야 함 |
| 속도 | 5% | 반복 실패 또는 비교에 사용할 수 없는 지연 |
| 비용 | 5% | 사전에 정한 실험 예산 초과 |

초기 5건 합격 기준:

- 가중평균 4.0/5 이상
- 사실성, 핵심 누락, 화자 구분 각각 4.0 이상
- 개인정보 5.0
- 치명적 오류 0건
- 구조화 응답 성공률 100%
- 메모로 쓰기 위한 수정시간 중앙값 3분 이하

5건은 연결과 치명적 오류 확인을 위한 값이다. 두 모델이 모두 통과하면
12건 이상으로 확대하며, 30건 미만 결과에는 `통계적으로 더 우수하다`는
표현을 사용하지 않는다.

## 11. 검증

### 백엔드

- 비로그인 401, 일반 사용자 403, 관리자만 성공
- 환경 스위치가 닫히면 외부 호출 없이 403
- 확인값이 없으면 외부 호출 없이 400
- 지원하지 않는 형식, 25MB 초과, 5분 초과 거절
- OpenAI 전사 한 번, ChatGPT와 Claude 요약 각 한 번
- 두 요약 공급자가 정확히 같은 가림 전사문을 받음
- 기존 네 구역 스키마를 벗어난 응답 거절
- 한 공급자 실패 시 부분 결과 반환
- 전사 실패 시 요약 호출 0회
- 임시 파일 삭제
- 녹음, 메모, 사용량, 결제 DB 행이 생기지 않음
- 로그에 파일명, 전사문, 요약문, API 키가 없음

### 프론트엔드

- 접근 제어와 관리자 레이아웃 유지
- 파일 미선택, 확인 미선택, 형식·크기 오류
- 전사 중, 요약 중, 오래 걸림 상태
- A/B 무작위 순서 렌더
- 모바일 세로, 데스크톱 두 열
- 전사문 접기·펼치기
- 부분 실패와 전체 실패
- 평가 전 모델명 숨김, 평가 후 공개
- 새로고침 후 결과 부재
- 쉬운 말, 긍정 안내, em dash 금지 검사를 통과

### 완료 기준

- Django 대상 테스트와 전체 테스트 통과
- PostgreSQL 관련 동시성 회귀 없음
- 프론트엔드 테스트와 Next 빌드 통과
- 비밀정보 검사 통과
- 합성 음성 한 건으로 실제 OpenAI·Claude API 연결 확인
- 두 결과와 전사문의 콘텐츠가 서버 로그와 DB에 남지 않음 확인
- 운영 기능 스위치가 계속 닫혀 있음 확인

## 12. 배포 경계

코드 병합과 운영 배포는 별도 단계다. 다음을 모두 확인한 뒤 PM의 명시적
운영 배포 승인을 받는다.

1. 로컬 자동 테스트와 빌드 성공

4. 비교 환경 스위치 기본값 `False`
5. 운영 녹음·AI 요약 환경 스위치가 계속 `False`
6. 롤백 경로와 API 키 폐기 경로 확인

## 13. 페르소나 협의체 기록

### 독립 의견

- 대표·기획: 제품화 전에 공급자 선택 근거를 얻되, 고객·결제·메모 구조를
  건드리지 않는다.
- 보험설계사: 문장 자연스러움보다 금액, 날짜, 고객 정정, 거절, 다음
  행동의 정확성이 우선이다.
- UI·UX: 모델 선입견을 줄이기 위해 A/B로 먼저 평가하고 나중에 모델명을
  공개한다.
- 데이터·AI 평가: 공통 전사문과 공통 스키마를 써야 요약 모델 차이를
  분리할 수 있다.
- 보안·개인정보: 합성 음성만 허용하고 콘텐츠를 DB, R2와 로그에 남기지
  않는다.
- QA: 한 건은 연결 확인일 뿐이며, 후보 비교에는 최소 5건이 필요하다.
- 그로스·마케팅: 합성 실험 결과를 실제 고객 가치나 외부 우수성 주장으로
  사용하지 않는다.
- 재무·인프라: 공급자별 처리시간, 토큰과 비용을 관찰하고 실험 예산을
  제한한다.

### 토론 1: 원음을 양쪽에 직접 보내야 공정한가

- 반론: 실제 전체 품질을 보려면 각 공급자의 원음 처리까지 함께 봐야 한다.
- 재반론: 전사와 요약을 한 번에 바꾸면 실패 원인을 알 수 없고, 현재 공개
  Claude API 오디오 지원도 확인되지 않았다.
- 결정: 이번 실험은 요약 품질만 비교한다. 음성 인식 비교는 이후 별도
  실험으로 분리한다.

### 토론 2: 결과를 저장해야 재검증할 수 있는가

- 반론: 결과 이력을 저장해야 나중에 다시 비교할 수 있다.
- 재반론: 초기 실험에서 콘텐츠 저장 구조를 만들면 고객 데이터 유입과
  보존 위험이 커지고 운영 기능 범위로 번진다.
- 결정: 이번 화면은 무저장으로 만들고, 사람이 사전 정답표를 기준으로
  현재 화면에서만 평가한다.

### 토론 3: 몇 건이면 결론을 낼 수 있는가

- 반론: 한두 건이면 연결과 대략적인 품질을 빠르게 볼 수 있다.
- 재반론: 작은 표본은 문장 유창성과 특정 상담 유형에 크게 흔들린다.
- 결정: 한 건은 연결 확인, 5건은 치명적 오류와 후보 확인, 12건 이상은
  다음 파일럿 후보 선정에 사용한다. 30건 미만에는 통계적 우월 표현을
  사용하지 않는다.
