# 인파 내부 오가닉 콘텐츠 12주 확장 설계

> 작성일: 2026-08-10
> 상태: PM 방향 승인, 구현 계획 작성 전
> 목표: 외부 채널 없이 인파 내부 콘텐츠에서 보험설계사 가입과 첫 사용까지 연결
> 공개 작성자: 전편 `인파 담당자`

## 1. 결정 요약

인파 블로그를 계속 운영하되, 네이버 블로그, 숏폼, 외부 커뮤니티 배포는 이번 범위에서 제외한다. 별도의 AI 콘텐츠 작업실도 만들지 않는다. 기존 원고, 이미지 manifest, 예약 공개, snapshot, 복원, 검색 계측 구조를 그대로 확장한다.

이번 작업은 다음 두 묶음으로 한정한다.

1. 가입 의도와 실무 활용도가 높은 신규 글 6편과 이미지 18개를 제작한다.
2. 기존 공개 글 6편의 제목, 도입부, 내부 링크, 마지막 행동 안내를 개선한다.

12주 동안 인파 내부에서 `검색 -> 블로그 -> 솔루션·가이드·무료 자료 -> 가입 -> 첫 분석·첫 공유`가 이어지는지 본다. AI는 조사, 초안, 문체 정리, 이미지 기획, 검색 정보, 내부 링크 설계에 최대한 활용하되, 사실 검수와 공개 책임은 `인파 담당자`가 가진다. 공개 화면에는 별도의 AI 작성 표시를 추가하지 않는다.

## 2. 목표와 성공 기준

북극성 지표는 **검색·AI 유입으로 가입한 뒤 7일 안에 첫 분석과 첫 공유를 모두 마친 보험설계사 수**다. 조회수와 검색 노출은 진단 지표로만 사용한다.

구현 성공 조건은 다음과 같다.

1. 신규 글 6편이 기존 25편과 검색 의도와 본문 결과물에서 중복되지 않는다.
2. 신규 글마다 편집형 대표 이미지, 정보 도식, 실제 인파 화면을 하나씩 가진다.
3. 기존 글 6편은 원래 사실 범위와 slug를 지키면서 인파 내부 다음 행동을 더 분명히 연결한다.
4. 모든 공개 작성자 표시는 API, 화면, 구조화 데이터에서 `인파 담당자`로 유지된다.
5. 가짜 경험, 가짜 고객, 가짜 인터뷰, 확인되지 않은 통계, 실제 고객 정보가 없다.
6. 글과 이미지가 자연스럽고 서로 다른 편집물처럼 보이며, 생성형 이미지 특유의 읽을 수 없는 글자나 비현실적 손·화면이 없다.
7. 예약 전 글은 목록, 상세, 관련 글, 사이트맵에 나타나지 않는다.
8. 기존 snapshot, digest, transaction, 복원 경로가 유지된다.
9. 글 열람과 마지막 행동 클릭을 기존 계측으로 확인할 수 있고, 가입의 최초 유입과 7일 활성화 지표에 연결된다.

12주는 표본을 만드는 첫 운영 주기다. 검색 순위, 가입 수, 활성화 수의 절대 목표치는 기존 표본이 작으므로 미리 만들지 않는다. 1~2주차 기준선과 같은 조건으로 이후 추세를 비교한다.

## 4. 신규 콘텐츠 6편

신규 글은 `직접 답변 -> 현장 상황 -> 확인 순서 -> 저장 가능한 표·체크리스트 -> 놓치기 쉬운 점 -> 인파 내부 다음 행동` 순서를 기본으로 한다. 기계적으로 같은 소제목을 반복하지 않고 주제에 따라 리듬과 구성을 바꾼다. 본문은 1,800~2,800자를 기준으로 하되 분량보다 구체성과 사실 밀도를 우선한다.

| # | 카테고리 | 제목 | 검색 의도 | 독자가 가져가는 결과물 | 인파 내부 연결 |
|---|---|---|---|---|---|
| 26 | 고객 늘리기 | 보험설계사 고객관리 프로그램을 고를 때 확인할 7가지 | 보험설계사 고객관리 프로그램 | 도구를 비교할 일곱 기준 | `/solutions/customer-management`, 고객관리표 |
| 27 | 보장분석 | 보험설계사 보장분석 프로그램, 자동 정리 뒤 확인할 6가지 | 보험설계사 보장분석 프로그램 | 자동 정리 결과 확인표 | `/solutions/policy-analysis`, 상담 체크리스트 |
| 28 | 고객 늘리기 | 보험설계사 영업관리, DB·TA·FA·청약을 다음 행동으로 연결하는 법 | 보험설계사 영업관리 프로그램 | 단계별 다음 행동 표 | `/solutions/sales-management`, 후속 연락 가이드 |
| 29 | 고객 늘리기 | 오래 연락하지 못한 고객에게 다시 연락하는 순서와 첫 문장 | 보험설계사 휴면 고객 관리 | 고객 상태별 다시 연락하는 순서 | 고객관리 솔루션, 후속 연락 가이드 |
| 30 | 고객 늘리기 | 고객 소개를 부탁하기 좋은 순간과 부담을 낮추는 문장 | 보험설계사 고객 소개 방법 | 상황별 소개 요청 문장과 확인표 | 소개 카드 글, 영업관리 솔루션 |
| 31 | 고객 늘리기 | 계약 후 고객관리, 30일·90일·180일에 챙길 일 | 보험설계사 계약 후 고객관리 | 세 시점의 관리 일정표 | 고객관리 솔루션, 연간 일정 글 |

### 글별 사실 경계

- 26: 특정 프로그램의 사용이 영업 성과를 보장한다고 쓰지 않는다. 고객 단계, 다음 연락, 일정, 자료 연결, 내보내기와 삭제 경로처럼 확인 가능한 기능 기준만 다룬다.
- 27: 자동 정리 결과를 최종 판단으로 표현하지 않는다. 원문 증권, 계약 조건, 금액, 담보명, 빠진 항목을 설계사가 확인하는 흐름으로 한정한다.
- 28: DB, TA, FA, 청약은 현장 용어를 처음 한 번 풀어 쓴다. 단계 이동을 고객의 가치 점수나 예상 계약률로 표현하지 않는다.
- 29: 오래 연락하지 않은 고객을 무조건 다시 접촉할 대상으로 보지 않는다. 연락 동의, 이전 요청, 마지막 대화, 중단 의사를 먼저 확인한다.
- 30: 소개를 압박하거나 보상을 암시하는 문장을 쓰지 않는다. 고객이 거절하거나 답하지 않아도 관계가 불편해지지 않는 선택권을 둔다.
- 31: 30일, 90일, 180일은 운영 예시일 뿐 법정·회사 의무 기간으로 표현하지 않는다. 소속 회사 절차와 고객 약속이 우선이라고 밝힌다.

보험·개인정보 관련 사실은 법령, 감독기관, 보험협회, 인파의 실제 공개 기능처럼 1차 출처를 우선한다. 모든 원고 메타데이터에 직접 URL과 `checked_at`을 남긴다. 검색 결과 요약, 다른 사업자의 광고 문구, 출처가 불분명한 커뮤니티 글은 사실 근거로 사용하지 않는다.

## 5. 기존 공개 글 6편 개선

기존 slug와 발행 시각은 유지한다. 검색 의도를 바꾸는 전면 개작이 아니라, 독자가 답을 더 빨리 얻고 인파 내부에서 다음 행동을 고를 수 있도록 개선한다.

| 기존 글 | 개선 내용 | 연결 목적지 |
|---|---|---|
| 01 신입 보험설계사, 지인 소개 다음에 할 일 | 첫 문단에 지인 이후 세 가지 고객 흐름을 직접 답변으로 제시 | 영업관리 솔루션 |
| 03 보험 증권 보는 법, 먼저 확인할 5가지 | 실제 확인 순서와 증권 자동 정리 뒤 재확인 항목을 분리 | 보장분석 솔루션 |
| 14 고객에게 보험 증권을 요청할 때 | 문자 예시 앞에 개인정보 최소 요청 원칙을 짧게 정리 | 첫 상담 가이드 |
| 15 고객 증권을 받은 뒤, 상담 전에 확인할 체크리스트 | 체크리스트를 무료 자료와 실제 인파 화면으로 연결 | 상담 체크리스트 |
| 16 보험 상담 뒤 기록할 5가지와 다음 연락 | 마지막 행동과 날짜를 기록하는 한 줄 예시 강화 | 후속 연락 가이드 |
| 18 보험설계사 고객관리표에 필요한 7개 칸 | 각 칸의 목적과 비워도 되는 정보를 더 분명히 설명 | 고객관리표 |

개선 글은 원래 제목의 핵심 검색 의도와 slug를 보존한다. title 또는 description을 다듬더라도 과장된 클릭 유도 문구를 넣지 않는다. `published_at`은 과거 발행 시각을 유지하고, 실제 콘텐츠 변경 시각만 `updated_at`과 sitemap `lastmod`에 반영한다.

## 6. 이미지 설계

신규 글 6편에 총 18개 자산을 만든다.

- 대표 이미지 6장: 1600×900 WebP, 자연광과 실제 사용감이 있는 편집 사진형 장면
- 정보 도식 6장: 1600×900 WebP, 인파 디자인 토큰으로 직접 렌더링한 체크리스트·흐름도
- 실제 화면 6장: 촬영용 합성 계정과 가상 데이터로 캡처한 인파 제품 화면

| 글 | 대표 이미지 장면 | 정보 도식 | 실제 화면 |
|---|---|---|---|
| 고객관리 프로그램 | 서로 다른 색의 무지 카드와 주간 수첩이 놓인 책상 | 프로그램 선택 7개 기준표 | 고객 목록과 다음 연락 화면 |
| 보장분석 프로그램 | 증권을 연상시키되 글자가 없는 서류 묶음과 태블릿 | 자동 정리 뒤 6개 확인 순서 | 보장 한눈표 또는 여러 증권 비교 화면 |
| 영업관리 | 네 구역으로 나눈 무지 업무 보드 | DB·TA·FA·청약 다음 행동 흐름 | 고객 단계별 화면 |
| 다시 연락하기 | 오래된 메모와 새 일정 카드가 함께 놓인 책상 | 진행중·보류·휴면·종료 상태별 확인 순서 | 고객 상태와 무접촉 표시 화면 |
| 고객 소개 | 무지 소개 카드와 휴대폰이 놓인 상담 테이블 | 소개 요청 전후 확인표 | 공개 소개 카드 화면 |
| 계약 후 관리 | 30·90·180 표시 탭이 있는 무지 플래너 | 세 시점 관리 일정표 | 고객 일정 또는 알림 화면 |

### 자연스러운 품질 기준

- 대표 이미지는 AI로 여러 후보를 만든 뒤, 실제 편집 사진처럼 보이는 한 장만 선택한다.
- 사람 얼굴, 실제 고객, 실제 증권, 보험사·상품 로고, QR, 읽을 수 있는 개인정보를 넣지 않는다.
- 이미지 안에 생성형 도구가 만든 글자를 넣지 않는다. 필요한 글자는 도식 제작 단계에서 직접 렌더링한다.
- 같은 렌즈, 같은 책상, 같은 조명, 같은 소품 구성을 반복하지 않는다.
- 비현실적인 손가락, 케이블, 그림자, 화면 반사, 종이 모서리가 있으면 폐기한다.
- 대표 이미지는 장식이므로 빈 alt를 사용하고, 정보 도식과 제품 화면에는 본문 정보를 반복하지 않는 구체적인 대체 문구를 둔다.

자산 경로와 manifest는 기존 규칙을 그대로 따른다.

- `inpa_fe/public/blog-assets/{slug}/cover.webp`
- `inpa_fe/public/blog-assets/{slug}/{role}-{8자리-content-hash}.webp`
- `inpa_fe/public/blog-assets/manifest.json`

manifest에는 생성·직접 제작·제품 캡처 여부, 사용 글, 개인정보 확인, 사용 권한을 내부 기록한다. 이 내부 provenance는 공개 작성자 표시에 노출하지 않는다.

## 7. AI 활용과 편집 책임

AI는 작업량의 약 80~90%를 맡는다.

1. 검색 의도와 기존 25편 중복 확인
2. 공식 출처 후보 수집과 사실 단위 정리
3. 글 구조, 초안, 표, 체크리스트 작성
4. 인파 브랜드 문체에 맞춘 재작성
5. 대표 이미지 후보와 도식 초안 제작
6. 검색 제목, 설명, 태그, 대체 문구 작성
7. 관련 글과 인파 내부 링크 추천
8. 금지 표현, 반복 문장, 링크, 이미지 누락 점검

공개 전 사람의 책임으로 다음을 확인한다.

- 출처 원문과 본문 주장이 일치하는지
- 실제 인파 기능과 화면 설명이 일치하는지
- 보험 판단, 계약 변경 권유, 성과 보장으로 읽히지 않는지
- 존재하지 않는 현장 경험이나 고객 발언을 쓴 것처럼 표현하지 않았는지
- `오늘은 알아보겠습니다`, 과도한 3단 나열, 결론 반복처럼 생성형 초안에서 자주 보이는 문장이 남지 않았는지
- 문단 길이와 문장 리듬이 자연스럽고 모바일에서 쉽게 읽히는지

브랜드 조직이 편집 책임을 지는 공식 콘텐츠이므로 공개 작성자는 `인파 담당자`로 통일한다. 별도 AI 작성 배지를 추가하지 않는다. 대신 출처, 확인일, 실제 기능 화면, 내부 자산 이력을 남겨 신뢰 근거를 콘텐츠 자체로 제공한다.

## 8. 12주 운영 일정

기존 25편의 마지막 예약 공개일인 2026-08-20 뒤부터 시작한다. 기존 글 6편은 구현 배포 때 한 번에 개선하고 실제 적용 시각을 기록한다. 신규 글은 격주 화요일에 공개하고, 사이 주는 직전 2주 유입과 전환을 확인한다. 모든 공개 시각은 KST다.

## 9. 릴리스와 데이터 보호

새 관리자 기능이나 모델을 만들지 않는다. 기존 `docs/blog-content/*.md`, `inpa_be/inpa/boards/blog_release.py`, `refresh_blog_content`, 프런트 자산 manifest와 검증 스크립트를 확장한다.

- 새 release version을 사용하고 승인 대상 slug를 31개로 고정한다.
- 기존 25편의 현재 DB 값을 적용 전 snapshot에 저장한다.
- 기존 법률 검토 대기 글 07, 08, 10은 제목, 본문, 공개 상태, 검토 필드를 변경하지 않는다.
- 개선 대상 6편만 승인된 필드를 쓰고, 나머지 기존 글은 어떤 콘텐츠 필드도 다시 쓰지 않는다.
- 신규 6편은 제목, 본문, 요약, 이미지, 검색 정보, 출처, 미래 공개 시각을 생성한다.
- 같은 버전과 같은 digest의 재실행은 no-op이다.
- 같은 버전에 다른 digest가 들어오면 중단한다.
- 적용 실패 시 transaction 전체를 롤백한다.
- 적용 전후 snapshot과 기존 restore 명령을 유지한다.

공개 가능 기준은 기존 중앙 QuerySet 규칙을 재사용한다.

```text
is_published = true
published_at is not null
published_at <= 현재 시각
법률 검토 대상이면 현재 콘텐츠와 결합된 유효한 검토 기록 존재
```

## 10. 인파 내부 연결과 계측

글마다 가장 중요한 마지막 행동은 하나만 강조한다.

- 프로그램 선택 글 3편: 관련 솔루션 확인 후 회원가입
- 실무 글 3편: 관련 가이드·자료를 먼저 사용하고 회원가입
- 기존 개선 글 6편: 글의 검색 의도와 가장 가까운 솔루션·가이드·자료 하나

관련 링크는 인파 내부 정식 주소만 사용한다. 고객 토큰 주소, 관리자 주소, 미공개 기능, 준비되지 않은 주소는 연결하지 않는다.

새 이벤트나 사용자 입력 수집을 만들지 않는다. 기존 `blog_view`, `blog_cta_click`, 최초 UTM 저장, 검색·AI 유입 가입자와 7일 활성화 집계를 재사용한다. 이벤트에는 slug, category, CTA 종류처럼 허용된 열거형만 보내고 검색어 원문, 고객 정보, URL 전체를 보내지 않는다. 계측 실패는 글 열람과 이동을 막지 않는다.

12주 판단 순서는 다음과 같다.

1. Google·네이버·AI 검색의 비브랜드 유입이 생겼는지
2. 어떤 글에서 솔루션·가이드·자료 이동이 일어났는지
3. 어떤 글이 가입의 최초 유입에 기여했는지
4. 그 가입자가 7일 안에 첫 분석과 첫 공유를 마쳤는지

표본이 작은 동안에는 주간 숫자의 증감으로 결론을 내리지 않는다. 4주 단위로 누적하고, 12주 뒤 주제 묶음별 유입·가입·활성화 흐름을 비교한다.

## 11. 오류 처리와 운영 안전

- 공식 출처가 확인되지 않거나 보험 판단으로 읽힐 수 있는 문장이 남으면 해당 글만 비공개로 둔다.
- 이미지 파일, manifest, content hash, 대체 문구 중 하나라도 맞지 않으면 릴리스 검사에서 중단한다.
- 미래 글이 공개 목록이나 사이트맵에 나타나면 배포를 중단한다.
- 실제 화면에 고객 정보, 실제 증권, 읽을 수 있는 전화번호가 보이면 해당 자산을 폐기하고 다시 촬영한다.
- 계측 도구가 실패해도 공개 글과 CTA 이동은 정상 동작한다.
- 적용 중 하나라도 실패하면 DB transaction과 snapshot으로 이전 상태를 유지한다.
- 배포 뒤 실제 주소 점검에서 문제가 나오면 신규 릴리스를 restore하고 프런트는 이전 Vercel 배포로 되돌린다.
