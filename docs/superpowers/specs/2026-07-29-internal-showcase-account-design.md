# 내부 시연 계정 설계

> 작성일: 2026-07-29  
> 상태: 사용자 승인 완료  
> 목적: 실제 잠재 고객에게 인파의 완성된 사용 흐름을 보여줄 수 있는, 풍부하고 자연스러운 가상 자료 전용 계정을 운영 서버에 만든다.

## 1. 확정 사항

- 로그인 아이디: `test@inpa.kr`
- 로그인 비밀번호: 사용자가 확정한 간단한 비밀번호(운영 서버 비밀 설정에만 저장)
- 용도: 대표님과 내부 구성원이 로그인해 화면을 보여주는 내부 시연용
- 화면에는 `데모`, `테스트`, `촬영`, `[DEMO]`, `[촬영]` 같은 표식을 노출하지 않는다.
- 모든 사람·연락처·보험·상담 내용은 가상 자료로 만든다.
- 실제 사용자, 실제 고객, 실제 게시판, 실제 운영 통계와 분리한다.
- 시연 중 고객 단계 이동, 메모 수정, 일정 추가 등 일반 기능은 시험할 수 있다.
- 자료가 흐트러지면 전용 초기화 명령으로 같은 상태를 다시 만든다.

## 2. 선택한 접근

### 전용 시연 계정과 전용 초기화 명령

기존 `seed_capture`는 랜딩 화면 촬영에 최적화돼 있지만, 한 고객에게만 상세 보장이 집중되고 계정·비밀번호·공유 카탈로그가 촬영 전용으로 고정돼 있다. 운영 시연 계정은 별도의 `seed_showcase` 명령으로 만든다.

새 명령은 기존 표준 담보 트리와 `[표준]` 호환 카탈로그를 읽기 전용으로 재사용한다. 시연용 보험 카탈로그, 게시글, 공지, FAQ, 요금제 같은 공용 행은 새로 만들지 않는다. 시연 자료는 원칙적으로 `test@inpa.kr` 계정이 소유한 행으로만 구성하며, 계정을 지우면 함께 정리되는 구조를 유지한다.

실제 고객 데이터를 복사하거나 익명화해서 사용하지 않는다. 원본이 없는 합성 자료를 코드로 결정론적으로 생성한다.

## 3. 시연 자료 구성

### 3.1 설계사 프로필

- 이름: 박도윤
- 소속: 한빛금융서비스
- 직책: 팀장
- 손해보험 중심 설계사
- 이메일 인증과 첫 설정은 완료 상태
- 관리자 권한 없음
- 비결제 내부용 Super 구독으로 전체 시연 화면을 볼 수 있도록 설정

프로필과 화면 어디에도 시연 계정임을 나타내는 문구를 넣지 않는다. 내부 시스템만 설정의 정확한 이메일로 시연 계정을 식별한다.

### 3.2 고객 50명

고객 이름, 생년월일, 성별, 직업, 전화번호, 유입 경로, 영업 단계, 진행 상태, 태그, 메모, 최근 연락일을 서로 모순되지 않게 연결한다.

- 영업 단계: DB 14명, TA 12명, FA 12명, 청약 12명
- 진행 상태: 진행 중 42명, 보류 4명, 휴면 3명, 종료 1명
- 유입 경로: 소개, 명함, 행사, 직접 등록, 셀프진단을 고르게 배치
- 태그: 신규, VIP, 갱신 예정, 가족 상담, 재상담 등
- 최근 6개월 동안 매달 자연스럽게 고객이 늘어난 흐름
- 이번 달 신규 고객, 오늘 연락한 고객, 오래 연락하지 않은 고객을 모두 포함

이름은 자연스러운 가명만 사용한다. 전화번호는 실제 가입자에게 배정되지 않는 프로젝트 표준 `010-1XXX-XXXX` 대역만 사용한다. 주소, 주민번호, 실제 이메일, 실제 회사의 개인 식별 정보는 넣지 않는다.

### 3.3 증권 80건

- 최근 6개월의 등록 흐름이 완만하게 증가
- 손해보험, 생명보험, 실손, 운전자, 건강, 암, 간병, 어린이보험 등 다양한 유형
- 월 보험료, 계약일, 만기일, 납입 회차가 서로 맞도록 계산
- 유지 중, 갱신 예정, 신규 청약 등 여러 상태
- 보험사·상품명은 실제 회사 실적처럼 오해되지 않도록 자연스러운 합성 이름 또는 일반적인 상품 유형 사용

대시보드의 월별 추이, 이번 달 보험료, 유지 현황과 고객 상세의 증권 목록이 같은 자료를 기준으로 계산되게 한다.

### 3.4 상세 보장 고객 8명

핵심 고객 8명은 각각 2~4개 증권과 12~25개 담보를 가진다. 연령대, 성별, 가족 상황, 보험 구성은 서로 다르게 만든다.
전체 상세 담보 행은 160건 이상으로 구성한다.

- 보장 한눈표에서 넉넉·적정·부족이 고르게 보이는 고객
- 여러 증권을 증권 A·증권 B로 나눠 비교할 수 있는 고객
- 기존 증권 여러 개만 비교하는 고객
- 보유 증권과 새 설계안을 나란히 보는 고객
- 갱신형·비갱신형·적립 보험료가 함께 있는 고객
- 일부 보장이 비어 있어 상담 포인트가 자연스럽게 보이는 고객
- 실손과 건강보험이 중복된 고객
- 가족 상담 흐름을 설명할 수 있는 고객

담보 연결은 기존 `[표준]` 호환 카탈로그와 고객별 `analysis_detail_override`를 사용한다. 표준 트리나 전역 정규화 사전의 연결을 변경하지 않는다.

### 3.5 목표·일정·예약·알림

- 최근 6개월 월 목표와 실제 실적
- 이번 달 일정 30건
- 오늘 일정 3건
- 생일·기념일, 만기·갱신, 고객 미팅, 업무, 기타 일정 모두 포함
- 월~금 예약 가능 시간
- 대기 예약 2건, 확정 예약 3건
- 알림 12건을 만들고 읽지 않은 알림과 읽은 알림을 함께 구성
- 할 일, 후속 연락, 갱신 안내가 고객 메모와 날짜에 맞게 연결

날짜는 명령 실행일을 기준으로 다시 계산한다. 다시 초기화해도 “오늘”, “이번 달”, “최근 6개월” 화면이 낡지 않는다.

### 3.6 공개 시연 화면

- 대표 고객 2명의 보장 공유 링크를 생성
- 예약 가능 시간을 보여주는 공개 예약 링크를 생성
- 토큰은 기존 서명·만료·속도 제한 규칙을 그대로 적용
- 게시판, 공지, FAQ, 블로그에는 시연 자료를 생성하지 않음

공개 링크는 링크를 가진 사람만 볼 수 있다. 일반 가입자에게 시연 고객이나 시연 증권이 노출되지 않는다.
기존 운영 관리자는 현재의 관리자 조회 권한으로 시연 계정을 관리 목적으로 확인할 수 있다.

## 4. 격리와 보안

### 4.1 계정 식별

- 서버 비밀 설정 `SHOWCASE_ACCOUNT_EMAIL=test@inpa.kr`
- 서버 비밀 설정 `SHOWCASE_ACCOUNT_PASSWORD`에는 사용자가 확정한 값을 저장
- `Profile.is_showcase`는 기본값 `False`, 이 계정만 `True`
- 비밀번호는 구현 소스, 배포 로그, 명령 출력에 하드코딩하지 않는다.
- 시연 계정 판별은 `Profile.is_showcase`와 설정 이메일을 함께 확인하는 한 곳의 공용 함수로 처리한다.

비밀번호가 매우 쉬운 것은 사용자가 의도적으로 선택한 운영 조건이다. 위험 범위를 줄이기 위해 아래 안전장치를 함께 적용한다.

### 4.2 권한과 외부 작동 제한

- 관리자·직원 권한 부여 금지
- 다른 사용자·고객 데이터 접근 금지
- 새 증권 스캔과 외부 AI 호출 차단
- 실제 이메일 발송과 Google 계정 연결 차단
- 실제 판촉물 주문과 결제·쿠폰 처리 차단
- 계정 탈퇴와 비밀번호 재설정 메일 발송 차단
- 준비된 분석, 비교, 일정, 예약, 알림은 정상 열람
- 고객 단계 이동, 메모, 태그, 일정 등 비용이 없는 내부 수정은 허용
- 기존 로그인 속도 제한과 계정 잠금 규칙 유지

차단 응답은 일반 사용자 화면의 긍정 안내 원칙을 따른다. 시연 계정이 아닌 사용자에게는 아무 영향이 없어야 한다.

### 4.3 운영 통계 제외

`Profile.is_showcase=True` 계정의 아래 자료는 운영 통계에서 제외한다.

- 가입·인증·활성화 전환
- 고객·증권·공유 사용량
- AI 비용과 사용량
- 알림 장애 감시의 가입자 집계
- 매출·요금제·쿠폰 지표
- 관리자 고객·활동 요약

기존 `@inpa.local` 제외 규칙과 시연 계정 제외 규칙을 공용 함수로 모아, 화면마다 조건을 복사하지 않는다.

## 5. 초기화와 삭제

### 5.1 생성·초기화

`python manage.py seed_showcase --apply`

- 설정된 이메일과 정확히 일치하는 계정만 대상
- 기존 계정이 있으면 `Profile.is_showcase=True`까지 확인한 뒤 소유 자료를 삭제하고 다시 생성
- 한 트랜잭션으로 실행
- 표준 담보·정규화 사전·게시판·요금제는 수정하지 않음
- 실행 결과에는 자료별 생성 수만 출력하고 비밀번호는 출력하지 않음

삭제 자동화의 보호 조건:

1. 이메일이 `SHOWCASE_ACCOUNT_EMAIL`과 정확히 일치
2. `Profile.is_showcase=True`
3. 관리자 권한이 없음
4. 명령에 `--apply`가 있음

네 조건이 모두 맞지 않으면 아무것도 지우지 않고 실패한다.

### 5.2 완전 삭제

`python manage.py seed_showcase --purge --apply`

- 위의 동일한 보호 조건 적용
- 시연 계정과 계정 소유 자료만 삭제
- 공용 표준 자료와 게시판은 변경하지 않음

## 6. 오류 처리

- 필수 서버 설정이 없으면 생성 전에 중단
- 표준 담보가 없거나 이름이 맞지 않으면 트랜잭션 시작 전에 누락 목록 출력
- 생성 중 하나라도 실패하면 전체 롤백
- 중복 사용자, 관리자 권한, 예상 밖의 공용 행 변경을 발견하면 실패
- 외부 API는 호출하지 않으므로 부분 생성 상태가 남지 않음

## 7. 검증 기준

### 자동 검증

1. 로그인 아이디와 설정된 비밀번호로 로그인 성공
2. 고객 50명, 증권 80건, 상세 보장 고객 8명, 상세 담보 160건 이상 생성
3. 단계·상태·최근 6개월 목표·일정·예약·알림 분포 확인
4. 명령을 두 번 실행해도 최종 개수와 화면 상태가 동일
5. 다른 일반 사용자가 시연 고객·증권·일정을 조회하면 404
6. 공지·FAQ·블로그·게시글·요금제 개수와 내용이 실행 전후 동일
7. 표준 트리·정규화 사전·호환 카탈로그의 개수와 연결이 실행 전후 동일
8. 운영 통계에서 시연 계정 활동 제외
9. AI·실제 발송·주문·결제 경로 차단
10. `[DEMO]`, `[촬영]`, `데모`, `촬영용` 렌더 문자열 0건

### 실제 화면 검증

- 홈 대시보드
- 고객 단계별·목록
- 핵심 고객 8명의 상세·보장 한눈표
- 여러 증권 비교
- 일정·예약 요청
- 알림
- 공개 보장 공유 화면
- 공개 예약 화면
- 모바일 화면

### 운영 검증

1. 운영 명령 실행 전 대상과 공용 테이블 개수 기록
2. 운영 명령 실행
3. 사용자에게 별도로 전달된 확정 자격증명으로 로그인
4. 핵심 API를 실제 호출해 개수와 소유 격리 확인
5. 브라우저에서 주요 화면과 모바일 화면 확인
6. 공지·FAQ·블로그·요금제 공개 API에 시연 흔적이 없는지 재확인

## 8. 완료 조건

- 대표님이 확정한 간단한 자격증명으로 바로 로그인할 수 있다.
- 첫 화면부터 자료가 충분히 채워져 있고 빈 화면이나 임시 문구가 없다.
- 고객, 증권, 보장, 비교, 일정, 예약, 알림이 하나의 자연스러운 영업 흐름으로 이어진다.
- 시연 자료는 일반 사용자와 공개 게시판에 노출되지 않는다.
- 실제 개인정보, 실제 고객 자료, 실제 외부 발송, 새 AI 비용이 없다.
- 한 명령으로 안전하게 원상복구하거나 완전히 삭제할 수 있다.
