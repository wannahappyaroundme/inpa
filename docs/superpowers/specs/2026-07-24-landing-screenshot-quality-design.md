# 랜딩 제품 스크린샷 품질 개선 (2026-07-24)

## 배경 (PM 지시)
www.inpa.kr 랜딩의 제품 스크린샷 5장(대시보드/고객 관리/보장 정리/증권 비교/일정)이
(1) 저해상도로 흐리고, (2) 여백 없이 꽉 차 답답하고, (3) [DEMO]/[DEMO-H]/010-0000-0000 등
데모 티가 나는 데이터가 노출됨. PM 요구:

- 진짜 사용 중인 계정처럼 보일 것. 가명·가짜 데이터는 쓰되 [DEMO]/[가칭]식 표시는 절대 금지.
- 김인파/이인파/최인파 같은 자연스러운 가명. 데이터 볼륨 넉넉히, 다양한 기능이 한번에 보이게.
- 5장 모두 높이(비율) 통일 + 상하좌우 여백.
- 음성 녹음·AI 요약은 아직 미구현(2026-07-22 계획 문서만 존재) → 허위 화면 제작 금지,
  기능 배포 후 6번째 스크린샷으로 추가하는 것을 권고.

## 설계
1. **BE 표시 수정**: 히트맵 트리 payload 의 카테고리명에서 `[표준]` 시드 마커 제거
   (`analysis/views.py`, `/s` 공유 payload 의 기존 removeprefix 규칙과 동일화).
   실서비스 사용자 화면에도 노출되던 실결함. 회귀 테스트 추가.
2. **촬영용 시드** `seed_capture` (analysis app, 수동 전용, 배포 startCommand 제외):
   - 계정 capture@inpa.local(@inpa.local → cleanup_demo 정리 대상), Profile.name 박도윤.
   - 고객 30명(자연 가명, 유명인 동명 회피), 실제같은 전화번호, 단계/상태/태그/색/무접촉 분산.
   - 6개월 우상향 등록 증권 45건+3건(월 38.5만→115만), 납입회차 분산(유지 안정 다수 + 13/25회차 임박).
   - 김인파: 종합건강보험+실손 보유, '새 보장 설계안' 제안, 기준 12개 → 부족3/적정7/넉넉2 신호등.
   - 일정 19건(5분류), 예약 대기 1건+확정 1건, 미읽음 알림 3건, 월 목표 6개월.
   - 모든 증권 review_status=confirmed + analysis_included(비교/분석 선택 조건).
   - seed_normalization 의 실제 [표준] 트리 재사용(공유 마스터 무변경, [촬영] 카탈로그만 추가).
3. **촬영**: Playwright headless, deviceScaleFactor 2, 논리 1344x804 → 2688x1608 클립.
   페이지별 앵커(대시보드=main, 고객=단계 보드, 보장=기준 배너, 비교=보장 비교 차트, 일정=main).
   의견 FAB 숨김. 로그인은 localStorage inpa_token 주입.
4. **프레임**: 2880x1800(16:10) 캔버스, 배경 #F3F5F9(--canvas), 사방 여백(96~116px),
   하단 120px 페이드(잘린 카드가 자연스럽게 사라지게).
5. **FE**: `lib/landing-content.ts` 5장 모두 2880x1800 로 갱신, `privacyNote` 제거
   (전원 가상 인물이라 흐림 처리 불필요), 테스트 갱신.

## 검증

- 다각 검증 워크플로우(가짜 표시/사실성·카피/화질·구성 3렌즈 + 반박 검증).

## 재촬영 절차 (다음에 또 쓸 때)
```
cd inpa_be
python manage.py cleanup_demo          # 로컬 [DEMO] 잔재 정리(선택)
python manage.py seed_normalization    # 실제 표준 트리(없을 때만)
python manage.py seed_capture          # 촬영 데이터 (로그인/고객 id 출력)
# FE 프로덕션 빌드 후, 세션 스크래치의 capture.cjs + pad.py 실행(스펙은 본 문서 3~4항)
```
