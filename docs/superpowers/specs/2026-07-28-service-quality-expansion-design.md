# 인파 서비스 품질 확장 설계

- 일자: 2026-07-28
- 상태: 구현 완료·배포 대기
- 관련 협의: `2026-07-28-service-quality-expansion-council.md`
- 구현 범위: 릴리스 A-E
- 보류 범위: 릴리스 F 판촉물 가격·장바구니, PM 가격표 수령 후 별도 확정

## 1. 목표

1. 설계사가 담보명을 다시 입력하지 않고 전체 표준 담보의 기준금액만 빠르게 설정한다.
2. 가입으로 자연스럽게 이어지는 화법을 제공하되 검증되지 않은 결과·우월성·지급 가능성을 단정하지 않는다.
3. 프로필 성명과 게시판 본인 관리 결함을 바로잡는다.
4. 무료 1개월 혜택은 가입을 막지 않고 인증된 휴대전화 번호 기준으로 중복 수혜를 통제한다.
5. 설계사가 보험 가입 희망자에게 녹음 고지를 직접 읽고 동의를 확인한 뒤 녹음을 시작한다.
6. 신규 녹음은 30일간 보관하고 소유 설계사가 내려받을 수 있게 한다.
7. 판촉물은 공급 가격표를 받은 뒤 예상 금액과 견적 장바구니를 구현한다.

## 2. 공통 제품 원칙

- 화면에서만 가능해 보이고 실제 데이터에는 반영되지 않는 기능을 만들지 않는다.
- 모든 사용자 작성 데이터는 소유자 범위를 서버에서 강제한다.
- 고객명, 전화번호, 화법 본문, 녹음 내용은 사용 통계와 일반 로그에 남기지 않는다.
- 빈값은 미설정이며 인파가 임의 값을 채우지 않는다.
- 모바일·데스크톱·키보드 사용 흐름을 모두 검증한다.
- 각 릴리스는 별도 마이그레이션·검증·배포 단위로 진행한다.

## 3. 릴리스 A: 프로필 성명·게시판 본인 관리

### 3.1 프로필 성명

계정 설정의 첫 영역을 `기본 프로필`로 통합한다.

- 성명
- 소속
- 직책
- 휴대전화

`Profile.name`을 단일 원본으로 사용한다. 예약 설정, 소개 카드, 화법 변수는 별도 이름을 저장하지 않는다. 다른 화면에서는 값을 보여주고 `프로필에서 수정`으로 연결한다.

성명이 비어 있어도 로그인은 막지 않는다. 고객에게 공유하거나 예약 문구를 만들 때 다음 행동을 안내한다.

> 성명을 입력하면 고객 안내에 바로 반영돼요.

이메일 앞부분을 공개 작성자명이나 설계사명으로 대신 노출하지 않는다.

### 3.2 게시글·댓글 관리

게시글과 댓글 응답에 요청 사용자 기준의 `can_manage`를 제공한다.

- 작성자: `true`
- 관리자: `true`
- 그 외: `false`

프론트는 사용자 ID를 추론하지 않고 `can_manage`만으로 수정·삭제 버튼을 표시한다. 실제 PATCH·DELETE 권한 검사는 기존 서버 권한을 유지한다.

삭제 UX:

1. 수정·삭제가 포함된 더보기 메뉴
2. 삭제 확인 대화상자
3. 처리 중 버튼 비활성화
4. 성공 시 목록 이동 또는 댓글 제거
5. 실패 시 원래 상태 유지와 다시 시도 안내

### 3.3 승인 기준

- 내 글·댓글은 목록과 상세에서 수정·삭제가 보인다.
- 타인의 글·댓글에는 관리 버튼이 보이지 않고 직접 API 호출도 거부된다.
- 관리자는 관리 버튼을 사용할 수 있다.
- 작성자명은 성명을 우선 사용한다.

## 4. 릴리스 B: 전체 담보 기준표

### 4.1 담보 카탈로그

표준 담보 전용 읽기 API를 제공한다.

- 표준 담보 ID
- 대분류·중분류·담보명
- 적용 상품군
- 단위
- 정렬순서
- 사용자에게 저장된 기준값
- 기준 데이터 revision

미검증 금액과 레거시 차트 값은 응답하지 않는다.

### 4.2 저장 모델

기존 자유 문자열 기준을 표준 담보 FK에 연결한다.

- 표준 담보 FK는 삭제 보호
- 기존 담보명은 호환·감사용 스냅샷으로 유지
- 상품 범위는 `전체 상품`을 기본으로 하고 `생명`, `손해` 예외를 허용
- 전연령은 명시적인 기본 스코프로 표현
- 성별 공통과 남성·여성 예외를 분리
- 공통값 중복을 실제 PostgreSQL 유일 제약으로 방지

기존 데이터는 이름 exact match로 연결한다. 미매칭 값은 삭제하지 않고 `기존 직접 입력`으로 보존하여 설계사가 확인할 수 있게 한다.

### 4.3 적용 우선순위

같은 표준 담보에 여러 기준이 있으면 다음 순서를 사용한다.

먼저 분석 대상 보험과 일치하는 `생명` 또는 `손해` 예외를 찾고, 없으면 `전체 상품` 기본값으로 내려간다. 각 상품 범위 안에서는 다음 순서를 사용한다.

1. 정확한 연령+정확한 성별
2. 정확한 연령+성별 공통
3. 전연령+정확한 성별
4. 전연령+성별 공통

공통 담보는 생명·손해 어느 분석에서도 누락되지 않게 한다. 상품군 예외가 필요하면 상세 설정에서만 제공하고, 기본 화면에는 전체 담보를 한 번에 보여준다.

### 4.4 화면

기본 화면:

- 대분류별 접힘 영역
- 담보명
- 기준금액 입력
- 선택형 `넉넉 기준금액`
- `상세 설정`

탐색:

- 담보 검색
- 카테고리 접기·펼치기
- 입력한 담보만 보기
- 변경한 항목 수
- 하단 고정 `변경 내용 저장`

상세 설정:

- 20대·30대·40대·50대·60대 이상
- 남성·여성·성별 공통
- 상세값 삭제와 공통값으로 복귀

빈 금액은 DB 행을 만들지 않으며 판정도 표시하지 않는다. 상한을 입력하지 않았다고 120% 같은 값을 자동 생성하지 않는다.

### 4.5 저장

- 변경된 행만 원자적으로 일괄 저장한다.
- revision으로 다른 기기의 동시 수정을 감지한다.
- 충돌 시 서버 값을 덮어쓰지 않고 최신 내용을 다시 확인하게 한다.
- 부분 저장은 허용하지 않는다.

### 4.6 승인 기준

- 표준 담보가 페이지 누락 없이 모두 보인다.
- 빈 금액은 미설정으로 남는다.
- 공통 담보가 실제 분석 판정에 적용된다.
- 4단계 우선순위가 백엔드와 화면에서 동일하다.
- 수십 개 기준을 저장하다 실패해도 일부만 반영되지 않는다.

## 5. 릴리스 C: 화법 전면 개정·내 템플릿·공유

### 5.1 카피 원칙

모든 기본 화법은 다음 구조로 다시 작성한다.

> 확인된 내용 → 고객에게 필요한 가치 → 작은 다음 행동 → 두 가지 선택지

다음 유형은 제거한다.

- 무기한 연기: `편하실 때`, `천천히`, `언제든`
- 소극적 종료: `결정은 고객님 몫`, `마음에 걸리는 부분이 있으면`
- 검증되지 않은 사회적 증거: `보험료를 아낀 분도 많아요`
- 결과 단정: `유리하다`, `받을 수 있는 돈`, `바꿀 필요 없다`
- 일반화: `예전 상품은 약하다`
- 사실과 다른 방어: `권하려는 것은 아니다`

가입 전환은 압박이나 공포가 아니라 다음 행동을 구체적으로 만드는 방식으로 강화한다.

예시:

> 오늘 확인한 보험료와 보장 내용을 한 번 더 점검한 뒤 신청 절차를 이어가겠습니다. 지금 진행할지, 조정할 항목부터 함께 볼지 말씀해 주세요.

30개 기본 화법은 실제 분석 결과가 필요한 문장과 범용 문장을 구분한다. 분석 결과가 없는 범용 템플릿은 판정형 문장을 포함하지 않는다.

### 5.2 템플릿 구조

기본 화법:

- 운영 원본
- 버전 관리
- 사용자가 직접 덮어쓰거나 삭제하지 않음
- 사용자별 숨기기와 기본값 복구 가능

내 템플릿:

- 기본 화법에서 `내 템플릿으로 저장`
- 새 템플릿 직접 추가
- 제목, 본문, 분류, 채널, 정렬순서, 사용 여부
- 수정, 복제, 삭제
- 소유자 범위와 소프트 삭제

템플릿에는 `{고객명}` 같은 변수만 저장한다. 고객명이 치환된 최종 문장은 저장하지 않는다.

### 5.3 화면

- 상단 `나만의 화법 추가`
- 필터 `전체`, `나만의 화법`, `기본 화법`
- 카드 메뉴 `수정`, `복제`, `삭제/숨기기`, `기본값으로 되돌리기`
- 주 버튼 `공유`

공유 버튼은 모든 기기에서 인파 공유창을 먼저 연다.

- `문구 복사`: 항상 제공
- `기기에서 공유`: Web Share 지원 기기에서 제공
- 직접 선택 가능한 읽기 영역
- 공유 취소와 실제 오류를 구분
- 복사 성공·실패를 화면 읽기 도구에도 안내

### 5.4 승인 기준

- 기본 화법 30개가 카피 원칙을 통과한다.
- 사용자가 내 템플릿을 추가·수정·삭제할 수 있다.
- 다른 설계사의 템플릿에 접근할 수 없다.
- 모바일과 데스크톱 모두 공유와 복사를 완료할 수 있다.
- 고객명과 문구 본문이 분석 이벤트·오류 로그에 남지 않는다.

## 6. 릴리스 D: 무료 1개월 수혜 중복 방지

### 6.1 정책

- 회원가입과 계정 생성은 휴대전화 중복 때문에 막지 않는다.
- 무료 1개월 혜택 활성화 직전에 SMS 인증을 요구한다.
- 같은 인증 번호는 같은 무료 1개월 혜택을 한 번만 받는다.
- 첫 유료결제 보너스 등 다른 혜택은 별도 `benefit_code`로 관리한다.
- PASS/CI는 이번 범위에 포함하지 않는다.

SMS는 현재 번호 통제를 확인하는 수단이며 사람을 평생 고유 식별한다고 표현하지 않는다.

### 6.2 데이터

인증 신원:

- 사용자
- 인증 제공사
- 전화번호 HMAC
- HMAC 키 버전
- 마스킹 번호
- 인증 시각
- 제공사 거래 식별자
- 교체·철회 시각

수혜 원장:

- 전화번호 HMAC
- 혜택 코드
- 정책·캠페인 버전
- 상태
- 지급 시각·만료 시각
- 사용자 참조는 계정 삭제 시 `SET_NULL`
- 관리자 예외 사유·처리자·처리 시각

`(전화번호 HMAC, 혜택 코드)`를 유일키로 사용한다. 캠페인명이나 쿠폰 코드가 바뀌어도 같은 무료 1개월 혜택을 다시 지급하지 않는다. 첫 유료결제 보너스처럼 성격이 다른 혜택만 별도 혜택 코드를 사용한다.

전화번호 원문은 중복 판정 원장에 보관하지 않는다. 수혜 원장은 무료 1개월 프로그램 운영 기간과 확정된 분쟁 대응 기간 동안만 유지한다. 정확한 종료 후 보유기간과 고지 문구는 운영 배포 전에 개인정보 처리방침과 함께 확정한다.

### 6.3 흐름

1. 무료 혜택 신청
2. SMS 인증번호 발송
3. 짧은 만료시간 안에 인증
4. 서버 트랜잭션으로 수혜 원장 확인
5. 처음이면 혜택 지급
6. 중복·재할당·공용번호 가능성이 있으면 혜택을 보류하고 수동심사 안내

수동심사:

- 연락 이메일
- 마스킹 전화번호
- 이전 가입 가능 사유
- 처리 상태와 예상 안내
- 관리자 승인·반려·사유 기록

신분증과 민감한 자료를 일반 이메일로 받지 않는다.

### 6.4 보안

- 전화번호·계정·IP별 발송 제한
- 인증번호 만료·시도 횟수 제한
- 인증번호 재사용 방지
- 계정 존재 여부와 무관한 동일 응답
- 지급 트랜잭션 잠금과 DB 유일 제약
- 제공사 콜백 서명 검증
- HMAC 키 회전 가능 구조

### 6.5 승인 기준

- 같은 인증 번호가 새 이메일·Google 계정·탈퇴 후 재가입으로 혜택을 다시 받을 수 없다.
- 동시 신청에서도 한 번만 지급된다.
- 중복 번호 사용자는 가입이 아니라 혜택만 보류된다.
- 수동심사 결과와 사유가 관리자 화면에 남는다.
- 원문 전화번호와 인증번호가 로그에 남지 않는다.

## 7. 릴리스 E: 상담 녹음 고지·다운로드·30일

### 7.1 안내의 화자와 청자

이 안내 화면의 사용자는 보험설계사다.

- 인파: 설계사에게 고지 절차와 읽을 문구를 보여준다.
- 설계사: 보험 가입 희망자에게 문구를 직접 읽는다.
- 보험 가입 희망자: 녹음 동의 여부를 설계사에게 답한다.

고객 공개 화면에 인파가 같은 문구를 직접 띄우는 기능으로 구현하지 않는다. 기존 고객 본인 전자 동의 링크는 별도의 선행 동의로 유지한다.

### 7.2 녹음 시작 전 화면

적색 계열 안내 카드:

> 녹음 전 필수 안내
>
> 보험 가입 희망자에게 아래 문구를 직접 읽고 동의를 확인해 주세요.
>
> “본 상담은 상담 내용을 정확히 기록하고, 향후 상담 내용과 보험금 청구 관련 안내를 확인하는 참고자료로 활용하기 위해 녹음합니다. 원본은 인파에 30일 동안 보관된 뒤 자동 삭제됩니다. 녹음에 동의하시나요?”

필수 확인:

> 보험 가입 희망자에게 위 내용을 안내했고, 녹음 동의를 확인했습니다.

이 확인 전에는 녹음 시작 버튼을 비활성화한다. 보험 가입 희망자가 동의하지 않으면 `상담 메모로 기록하기`를 다음 행동으로 제공한다.

클라이언트 체크만 믿지 않는다. 녹음 업로드 세션 요청에 고지 완료 여부와 고지문 버전을 포함하고, 서버가 다음을 저장한다.

- `notice_version`
- `notice_attested_at`
- 고지문 스냅샷 해시
- 확인한 설계사

매 녹음 세션마다 다시 확인하며 이전 체크를 재사용하지 않는다.

### 7.3 동의와 30일 보관

- 고객 본인 전자 동의는 계속 필수다.
- 상담 녹음 동의문을 30일 보관 내용으로 새 버전 발행한다.
- 새 버전에 동의한 신규 녹음만 30일을 적용한다.
- 기존 7일 동의로 생성된 녹음은 원래 만료일을 유지한다.
- 모델의 168시간 상한, 설정, capability API, R2 메타데이터, 사용자·관리자 화면의 하드코딩을 서버 정책 하나로 통합한다.
- 배포 전 R2 자체 수명주기가 7일로 설정되어 있지 않은지 확인한다.

### 7.4 다운로드

소유 설계사 전용 다운로드 API를 추가한다.

- 5분 이하 만료
- `Content-Disposition: attachment`
- 안전한 파일명 `상담녹음_YYYYMMDD.ext`
- 실제 MIME·codec 기반 확장자
- 만료·삭제·동의철회 상태 재검증
- 타인과 일반 관리자 접근 차단

다운로드 이벤트에는 사용자·녹음 ID·결과·시각만 남긴다. 고객명, 저장 키, 서명 URL은 로그에 남기지 않는다.

### 7.5 향후 보관 로드맵

이번 릴리스에서는 30일만 활성화한다.

- 90일 유료 보관
- 장기 보관

위 항목은 유료 플랜, 저장비용, 재동의, 다운로드 감사, 동의철회, 탈퇴·다운그레이드 시 삭제 정책을 확정한 뒤 별도 설계한다. 기존 녹음을 플랜 변경만으로 자동 연장하지 않는다. 문자 그대로의 `영구 보관`은 사용하지 않고 종료 조건이 있는 보관 정책으로 정의한다.

### 7.6 승인 기준

- 고객 본인 최신 동의와 설계사의 매회 구두고지 완료 확인이 모두 있어야 녹음을 시작한다.
- 기존 녹음은 7일, 신규 녹음은 30일 경계를 유지한다.
- 소유 설계사만 녹음을 내려받을 수 있다.
- 만료·삭제·동의철회 후 재생과 다운로드가 모두 차단된다.
- 정리 작업이 30일 경계에서 원본과 DB 상태를 일치시킨다.

## 8. 릴리스 F: 판촉물 예상 금액·장바구니, 입력 대기

### 8.1 현재 결정

PM이 실제 공급 가격표를 한 번에 전달할 때까지 구현하지 않는다. 임시 가격, 샘플 가격, 화면 전용 가격을 만들지 않는다.

가격표 수령 시 필요한 항목:

- 상품별 최소 수량·수량 단위
- 수량 구간별 단가
- 기본 제작비
- 옵션별 추가금
- 부가세 포함 여부
- 배송비 계산 방식
- 적용 시작일

### 8.2 승인된 구조

가격표 수령 후 다음을 별도 설계·구현한다.

- 관리자 가격 CRUD
- 서버 예상 견적
- 소유자 범위 서버 장바구니
- 수량·옵션 변경 시 서버 재계산
- 여러 품목 원자적 견적 요청
- 주문 당시 가격·옵션·수량·VAT·배송비·총액 스냅샷
- 가격 변경 시 재확인
- 결제 제외, `예상 금액 + 견적 요청`까지만 제공

## 9. 릴리스 순서와 배포 경계

1. A: 프로필 성명·게시판 본인 관리
2. B: 담보 전체 기준표
3. C: 화법 교정·내 템플릿·공유
4. D: 무료 1개월 SMS·수혜 원장
5. E: 녹음 고지·다운로드·30일
6. F: 판촉물, 가격표 수령 후 별도 착수

무료 혜택을 크게 노출하기 전 D를 완료한다. 녹음 기능 게이트를 열기 전 E를 완료한다. A-E 구현은 하나의 배치로 완료됐지만 아직 어느 릴리스도 배포되지 않았다. 향후 단계적 운영 배포 전에는 각 릴리스와 해당 게이트가 테스트·빌드·실제 브라우저 확인, 해당하는 PostgreSQL·R2·SOLAPI·실기기 요건, PM 승인, 운영 배포, 실제 URL 검증을 순서대로 통과해야 한다. F는 가격표를 받기 전까지 비범위로 유지한다.

### 13.2 실제 브라우저 확인 상태

이 검증 세션에는 연결 가능한 인앱 브라우저가 없었다. 따라서 다음 happy path는 자동화·단위 테스트 근거는 있으나 실제 브라우저 결과는 **미검증**이며 배포 전 게이트로 남는다.

3. 전체 담보 기본값과 상세 예외 저장 후 히트맵 판정 반영
4. 기본 화법 공유, 개인 화법 추가·수정·삭제
