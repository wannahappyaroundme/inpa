# 보험설계사 상담 예약 링크, 시간을 주고받지 않고 약속 잡는 법

<!-- blog-body -->

보험설계사 상담 예약 링크는 업무시간과 앞뒤 여유시간, 이미 잡힌 일정을 먼저 반영한 뒤 고객에게 빈 시간을 보여주는 방식으로 운영해야 합니다. 고객이 시간을 고르면 곧바로 확정되는 것이 아니라 예약 요청으로 들어오고, 설계사가 내용을 확인해 수락하거나 거절한 뒤 확정 약속이 됩니다. 이 흐름을 안내하면 “언제 되세요?”를 여러 번 주고받는 일을 줄일 수 있습니다.

이 글은 약속을 처음 잡는 과정에 집중합니다. 이미 확정된 상담의 전날·당일 안내 문구나 해마다 반복되는 생일·만기 일정과는 목적이 다릅니다.

## 업무시간은 실제로 상담 가능한 범위만 엽니다

월요일부터 금요일까지 같은 시간을 한꺼번에 열기보다, 이동과 준비를 포함해 반복적으로 지킬 수 있는 시간대를 정합니다. 예를 들어 화·목 오후에 온라인 상담을 받고 수요일은 대면 상담을 잡는다면 각 요일의 실제 가능 시간을 따로 둡니다.

업무시간은 고객에게 항상 연락할 수 있다는 약속이 아닙니다. 예약 후보를 계산하는 바탕입니다. 휴가, 교육, 회사 행사처럼 특정 날짜에만 생기는 일정은 업무시간 자체를 지우지 말고 그 날짜의 예약 제외 일정으로 막는 편이 관리하기 쉽습니다.

## 앞뒤 여유와 예약 제외 일정을 함께 둡니다

상담이 40분이라도 연속해서 40분 간격으로 열면 기록과 이동 시간이 사라집니다. 상담 앞뒤 여유시간에는 이전 상담 정리, 고객 자료 확인, 이동, 접속 점검을 포함합니다. 대면 상담과 온라인 상담의 여유가 다르다면 더 긴 쪽을 기준으로 시작해 조정하세요.

| 설정 항목 | 정할 내용 | 화면에서 확인할 결과 |
|---|---|---|
| 업무시간 | 요일별 상담 시작·종료 시간 | 정한 요일과 시간만 후보로 보임 |
| 상담 길이 | 실제로 약속할 기본 시간 | 끝나는 시각이 다음 후보와 겹치지 않음 |
| 앞뒤 여유 | 준비·이동·기록에 필요한 분 | 연속 예약 사이에 빈 시간이 생김 |
| 예약 제외 일정 | 개인 일정, 교육, 확정 미팅 | 겹치는 후보가 고객 화면에서 빠짐 |
| 요청 확인 | 고객 이름, 연락 방법, 선택 시간 | 설계사가 수락·거절할 자료가 모임 |

## 고객에게는 요청 단계라고 분명히 알립니다

링크와 함께 “가능한 시간을 골라 요청해주세요. 내용을 확인한 뒤 확정 시간을 안내드릴게요”라고 적으면 고객이 선택하는 즉시 확정됐다고 오해하기 어렵습니다. 고객이 보는 화면에는 날짜, 시작 시각, 예상 상담 시간, 남길 기본 정보가 분명해야 합니다.

첫 예약 요청에는 이름이나 불릴 이름, 답을 받을 연락 방법, 상담 주제 정도면 흐름을 시작할 수 있습니다. 주민등록번호, 상세 병력, 가족 증권 전체를 예약 단계에서 받지 않습니다. 자료가 필요하면 요청을 확인한 뒤 목적, 필요한 면, 가릴 정보와 전달 방법을 따로 안내하세요.

## 설계사가 수락하거나 거절한 뒤 확정됩니다

![고객이 빈 시간을 골라 상담을 요청하는 공개 예약 화면](/blog-assets/보험설계사-상담-예약-링크/booking-request-screen-e4733033.webp)

예약 요청이 들어오면 같은 시간의 고객 미팅, 개인 일정, 앞뒤 여유를 다시 확인합니다. 가능한 요청은 수락해 확정하고, 일정이 맞지 않으면 거절한 뒤 고객과 다른 시간을 상의합니다. 수락 전에는 캘린더의 확정 약속처럼 안내하지 않습니다.

인파에서는 업무시간을 기준으로 빈 시간이 예약 링크에 보이고, 고객이 고른 시간은 요청으로 들어옵니다. 설계사가 수락하면 확정 일정으로 이어지며 구글 캘린더 연결을 사용하는 경우 확정 뒤 반영할 수 있습니다. 외부 캘린더 연결 여부는 실제 설정 화면에서 확인하세요.

## 확정 뒤에는 한 약속만 기준으로 안내합니다

확정 안내에는 고객 이름, 날짜와 요일, 오전·오후를 포함한 시각, 장소나 접속 방법, 변경을 요청할 경로를 적습니다. 이전에 제안했던 후보 시간은 지우고 최신 약속 하나만 남깁니다. 변경 요청이 오면 기존 일정을 정리한 뒤 새 요청이나 합의한 시간을 다시 확정합니다.

링크를 공개하기 전에는 가상 예약으로 처음부터 끝까지 시험합니다.

- 업무시간 밖의 후보가 보이지 않는가
- 기존 일정과 앞뒤 여유가 반영되는가
- 고객 선택이 요청 상태로 들어오는가
- 수락 전과 확정 뒤 안내가 구분되는가
- 거절한 시간이 다시 선택 가능한지 현재 정책과 맞는가
