# 인파 노트 브랜드 보이스와 원고 가이드

> 블로그 이름은 **인파 노트**입니다. 주 독자는 새내기 보험설계사이며, 목표는 검색으로 들어온 독자가 현장에서 다시 꺼내 쓰는 자료를 제공하는 것입니다.

## 1. 글의 목소리

1. **답부터 씁니다.** 첫 2~4문장에서 질문에 직접 답합니다.
2. **선배처럼 정리합니다.** 독자를 가르치거나 겁주지 않고, 상담 전에 함께 확인하는 말투를 씁니다.
3. **쉬운 말을 씁니다.** `자동 인식`, `단계별`, `고객`처럼 설계사가 바로 이해하는 표현을 고릅니다.
4. **계약별 차이를 남깁니다.** 담보 이름만으로 범위나 지급 여부를 단정하지 않습니다. 약관, 상품설명서, 증권, 보험회사 확인이 우선입니다.
5. **성과를 약속하지 않습니다.** 근거 없는 시간 절감, 예약률, 답장률, 계약 성과, 실제 후기처럼 보이는 사례를 쓰지 않습니다.
6. **다음 행동은 하나만 둡니다.** 본문은 제품 기능을 사실대로 한 번 연결하고, 상세 화면의 공개 CTA 한 곳에서만 시작을 권합니다.

## 2. 글 한 편의 구조

| 순서 | 요소 | 기준 |
|---|---|---|
| 1 | 제목 | 검색 질문을 쉬운 말로 표현 |
| 2 | 핵심 답 | 2~4문장, 조건과 예외를 함께 설명 |
| 3 | 짧은 본문 | 질문형 소제목 3~6개 |
| 4 | 실무 자료 | 표, 체크리스트, 문장 예시 가운데 최소 1개 |
| 5 | 합성 예시 | 실제 인물이나 계약으로 오해하지 않게 표시 |
| 6 | 흔히 놓치는 점 | 단정, 누락, 개인정보 과수집을 예방 |
| 7 | 저장용 체크리스트 | 상담 전 다시 볼 수 있는 짧은 목록 |
| 8 | 관련 글 | 승인된 정확한 slug로 맥락 링크 2개 |
| 9 | 인파 연결 | 현재 공개 중인 기능만 한 문단으로 설명 |

- 본문은 주제에 필요한 만큼 쓰며 대체로 1,500~2,500자를 권합니다.
- 사용자 화면에는 em dash를 쓰지 않습니다.
- `OCR`, `Kanban`, `lead`, 내부 검토 용어 같은 기술 말은 쓰지 않습니다.
- 본문에 정직성 문구를 반복하지 않습니다. 상세 화면이 공식 위치 한 곳에서 표시합니다.
- 공개 작성자는 코드가 `인파 담당자`로 표시합니다. 본문에 개인 이름이나 가상의 감수자를 만들지 않습니다.

## 3. 사실과 안전 기준

- 특정 보험사나 상품을 좋다고 표현하지 않습니다.
- `증권 A`와 `증권 B`는 같은 시각적 무게로 둡니다. 차이는 보여주되 결론은 만들지 않습니다.
- 담보 이름 정리는 탐색을 돕는 도구입니다. 같은 이름이나 같은 줄이 동일한 보장을 증명하지 않습니다.
- 정액형 보장의 중복과 실제 비용을 보상하는 보험의 비례보상을 구분합니다. 중복을 곧바로 낭비라고 부르지 않습니다.
- 고객 사례는 합성 또는 각색임을 제목, 본문 첫머리, 이미지 설명에서 분명히 밝힙니다.
- 안심 가이드 3편은 완성 원고로 보관하되 실제 법무 검토 기록 전에는 공개하지 않습니다.
- 법률 검토 기록은 검토된 글 버전과 결합합니다. 글을 임시저장한 뒤 별도 확인 단계에서 서버 시각으로 기록합니다. 검토 확인 요청에는 임시저장 응답의 콘텐츠 해시를 보내며, 다른 탭에서 글이 바뀌면 다시 확인하도록 차단합니다. 검토 뒤 제목, 본문, 요약, 대표 이미지, 분류, 태그 또는 검색 정보를 바꾸면 이전 기록을 지우고 다시 검토합니다.
- 검토를 마친 글에는 담당자 이름, 자격, 확인일만 공개합니다. 내부 검토 근거는 관리자 화면에만 남깁니다.

## 4. 릴리스 메타데이터

원고는 `blog-meta` JSON, H1, `blog-body` 순서로 저장합니다. `sources`에는 실제로 연 공식 원문만 기록하고, 출처 제목과 날짜는 원문 표기를 따릅니다.

- 기존 slug와 파일명은 바꾸지 않습니다.
- 대표 이미지 경로는 `/blog-assets/{slug}/cover.webp`입니다.
- 안심 가이드 slug 07, 08, 10은 `is_published: false`, `review_gate: "legal"`, `legal_review: null`입니다.
- 배포 원고에는 법률 검토 기록을 넣지 않습니다. 검토와 공개는 관리자 화면의 별도 확인 단계에서만 진행합니다.
- 그 밖의 기존 글은 `is_published: true`, `review_gate: "none"`, `legal_review: null`입니다.
- 모든 출처는 `checked_at: "2026-08-03"`을 포함합니다.

## 6. 이미지와 링크

- 대표 이미지는 본문에 다시 넣지 않습니다.
- 본문 이미지는 `/blog-assets/` 아래의 승인된 경로만 사용합니다.
- 정보 이미지는 아래 HTML 표나 문장으로 같은 내용을 이해할 수 있게 합니다.
- 공개 글은 비공개 안심 가이드로 연결하지 않습니다.
- 외부 이미지와 보험사 자료 화면은 넣지 않습니다.

## 7. 발행 전 확인

- [ ] 공식 원문을 직접 열었고 메타데이터에 확인일을 기록했는가
- [ ] 계약마다 달라지는 내용을 하나의 정답처럼 쓰지 않았는가
- [ ] 근거 없는 수치, 시간, 성과, 후기 문장을 지웠는가
- [ ] 본문에 관련 글 링크가 정확히 2개 있는가
- [ ] 본문에 정직성 문구나 별도 작성자 이름이 없는가
- [ ] 안심 가이드 공개 상태와 법무 검토 기록이 정확한가
- [ ] 개인정보, 읽을 수 있는 증권 정보, 보험사·상품 이름이 없는가
- [ ] 공개 중인 인파 기능만 설명했는가
