# 보험설계사 고객 자료, 파일 이름과 보관 위치를 정하는 법

<!-- blog-body -->

보험설계사 고객 자료는 `고객표시이름_자료종류_상담일` 한 가지 규칙으로 이름을 붙이고, 고객별 폴더 안을 자료 종류와 연도 정도로만 나누면 다시 찾기 쉽습니다. 폴더 깊이는 세 단계 이하로 유지하고, 파일 이름에는 주민등록번호·전화번호·병력 같은 민감한 내용을 넣지 마세요. 보관 이유와 삭제를 다시 확인할 날짜도 파일 목록 옆에 함께 남깁니다.

자료를 많이 저장하는 것이 정리의 목표는 아닙니다. 이번 상담에 필요한 범위를 알고, 받은 경로와 보관 위치를 하나로 정하며, 목적이 끝난 자료를 확인하는 흐름까지 있어야 합니다.

## 파일 이름은 세 조각이면 충분합니다

기본 공식은 `고객표시이름_자료종류_상담일`입니다. 날짜는 `YYYYMMDD`처럼 한 가지 형식으로 맞춥니다.

- `김고객_증권_20260922.pdf`
- `이고객_상담질문_20261006.docx`
- `박고객_확인메모_20261020.pdf`

고객표시이름은 업무 안에서 구분할 수 있는 이름이나 별칭을 사용합니다. 주민등록번호, 전화번호, 상세 진단명, 가족관계, 계좌번호를 파일 이름에 넣으면 파일 목록과 검색 결과만으로도 민감한 내용이 드러날 수 있습니다. 자료종류도 `증권`, `상담질문`, `확인메모`처럼 넓은 분류로 두고 병력이나 상담 결론을 제목에 옮기지 않습니다.

버전을 구분해야 한다면 `수정본`, `최종`을 계속 붙이기보다 확인 날짜를 바꾸고 이전 파일의 상태를 목록에 남깁니다. 같은 날짜에 여러 파일이 생겼을 때만 `_01`, `_02`처럼 짧은 순번을 덧붙이세요.

## 폴더는 세 단계보다 깊게 만들지 않습니다

권장 구조는 `고객 자료 / 고객표시이름 / 연도 또는 자료종류`입니다. 여기서 한 단계를 더 내려가면 저장할 때마다 위치를 고민하고, 같은 파일이 여러 경로에 복사되기 쉽습니다.

| 단계 | 폴더 예시 | 확인할 점 |
|---|---|---|
| 1 | 고객 자료 | 소속 회사에서 허용한 보관 위치인가 |
| 2 | 김고객 | 다른 고객 자료가 섞이지 않았는가 |
| 3 | 2026 또는 증권 | 팀에서 한 가지 기준으로 쓰는가 |
| 파일 | 김고객_증권_20260922.pdf | 민감한 내용이 이름에 드러나지 않는가 |

![파일 이름과 세 단계 폴더, 삭제 확인일을 잇는 정리 흐름](/blog-assets/보험설계사-고객-자료-파일-정리/file-folder-deletion-flow-pending.webp)

개인 메신저, 휴대전화 내려받기 폴더, 개인 클라우드, 업무 저장소에 같은 파일을 복제하면 어느 것이 최신인지 알기 어렵습니다. 고객과 합의한 전달 경로에서 받은 뒤 소속 회사가 정한 위치로 옮기고, 임시 사본을 어떻게 정리할지도 함께 확인하세요.

## 파일 목록에는 네 가지를 따로 적습니다

파일 이름만으로는 왜 보관하는지와 언제 다시 볼지 알 수 없습니다. 고객관리표나 별도 자료 목록에 다음 네 칸을 둡니다.

1. 자료 종류와 파일 이름
2. 받은 날짜와 전달 경로
3. 이번 업무에서 쓰는 목적
4. 삭제 또는 계속 보관할지 다시 확인할 날짜

보관 기간은 모든 고객에게 임의의 같은 숫자를 붙이지 않습니다. 수집 목적, 고객과의 관계, 소속 회사 절차, 개인정보 처리방침과 적용되는 기준을 먼저 확인합니다. 삭제 확인일은 그날 자동으로 지우겠다는 뜻이 아니라, 보관 이유가 남아 있는지 담당자가 다시 보는 날짜입니다.

## 새 자료를 받을 때 중복부터 찾습니다

새 증권을 받으면 곧바로 다른 폴더를 만들지 말고 같은 고객, 같은 자료종류, 같은 상담일 파일이 있는지 검색합니다. 이전 자료를 바꾸는 경우에는 원문을 덮어쓰기보다 확인 날짜와 상태를 목록에서 구분합니다. 어떤 파일이 고객이 보낸 원본이고 어떤 파일이 업무용 사본인지도 혼동하지 않게 표시하세요.

![고객 상세에서 등록된 보험 자료를 고객별로 확인하는 화면](/blog-assets/보험설계사-고객-자료-파일-정리/customer-policy-list-pending.webp)

화면에서 고객별 증권을 연결하더라도 파일 이름과 보관 경로의 기본 원칙은 같습니다. 자동 정리된 값은 원문 파일을 대신하지 않으므로, 원문 위치를 다시 찾을 수 있어야 합니다. 반대로 분석에 쓰지 않는 식별정보를 편의를 위해 별도 파일명이나 메모로 복사할 이유도 없습니다.

## 매주 10분, 세 묶음만 확인합니다

- 이번 주 받은 파일 가운데 이름 규칙이 다른 것
- 임시 내려받기나 메신저에 남은 중복 사본
- 삭제 확인일이 지났지만 보관 이유를 다시 보지 않은 자료

한꺼번에 전체 저장소를 정리하려 하면 중단하기 쉽습니다. 새로 받은 자료부터 같은 규칙으로 저장하고, 매주 세 묶음을 확인하면 오래된 폴더도 조금씩 정돈됩니다.

**오늘 할 일: [빈 고객 관리표를 내려받아](https://www.inpa.kr/resources/customer-management-sheet) `자료 이름`, `받은 날짜`, `보관 목적`, `삭제 확인일` 네 칸을 덧붙이고, 가상 파일 세 개로 규칙을 시험해보세요.**
