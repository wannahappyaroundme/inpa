# 보장분석 결과를 고객에게 공유할 때, 먼저 설명할 5가지

<!-- blog-body -->

보장분석 결과를 고객에게 공유할 때는 공개 화면에 실제로 보이는 것부터 설명하세요. 인파의 고객 공유 화면에는 월 보험료, 총 납입 보험료, 공유 당시 담보명과 담보별 보유 금액이 사실 중심으로 표시됩니다. 공개 공유 화면에는 설계사 기준과 부족·적정·넉넉 표시가 포함되지 않습니다. 상품 선택이나 계약 변경 결론도 제공하지 않습니다.

설계사가 원문 증권, 담보 연결, 설정 기준을 확인하는 과정은 링크를 만들기 전 내부 준비입니다. 고객이 보는 화면과 설계사가 준비할 화면을 먼저 분리하면, 고객에게 보이지 않는 값을 화면에 있는 것처럼 설명하는 일을 피할 수 있습니다.

## 1. 공유 전 내부 확인과 공개 화면을 나눕니다

설계사 화면에서는 등록한 보험의 계약자·피보험자, 보험료와 기간, 원래 담보명, 공통 보장 항목의 연결을 원문과 대조합니다. 금액을 알 수 없는 항목은 임의의 숫자로 채우지 않고 확인할 줄로 남깁니다. 이 과정은 공개 링크를 만들기 전에 설계사가 자료의 정확성을 점검하는 단계입니다.

설계사가 직접 확인해 저장한 기준이 있다면 내부 분석 화면에서 부족·적정·넉넉 상태를 볼 수 있습니다. 이 상태는 설계사 내부 준비에만 사용합니다. 고객 공개 화면은 등급 없이 보유 금액과 보험료만 표시하며 기준 금액과 등급을 보내지 않습니다. 내부 색을 고객 화면의 판단이나 권장 방향으로 옮겨 설명하지 마세요.

## 2. 고객이 실제로 보는 네 가지를 설명합니다

고객 화면은 마스킹된 이름 아래 공유 당시 보장 현황을 보여줍니다. 최신 공유 방식에서 시각이 보인다면 이는 공유 기록을 만든 시각이며, 증권의 계약 기준일이나 보장 확인 기준일을 뜻하지 않습니다.

| 공개 화면에서 보이는 것 | 화면의 뜻 | 고객에게 설명할 문장 |
|---|---|---|
| 월 보험료 | 등록된 보유 보험에서 계산된 월 보험료 합계 | “공유할 때 등록돼 있던 월 보험료 합계예요.” |
| 총 납입 보험료 | 등록된 보유 보험의 총 납입 보험료 합계 | “화면에 정리된 총 납입 보험료예요.” |
| 공유 당시 담보 | 공통 담보명 가운데 보유 금액이 있는 항목 | “공유 당시 금액이 등록된 담보만 모아 보여드려요.” |
| 담보별 보유 금액 | 해당 공통 담보 항목에 정리된 금액 | “이 금액은 등록된 정보를 같은 항목으로 모은 값이에요.” |

![설계사 내부 원문·기준 확인과 고객 공개 화면의 보험료·담보 보유 금액을 분리하는 다섯 단계](/blog-assets/보장분석-결과-고객-공유/share-explanation-five-a52602c6.webp)

보험료 값을 알 수 없으면 화면에 `-`로 표시될 수 있습니다. 담보는 보유 금액이 있는 항목만 목록에 나타납니다. 공개 목록에 보이지 않는 항목을 원문상 보장이 없다는 뜻으로 바꾸어 말하지 말고 설계사 내부 자료에서 따로 확인하세요.

## 3. 공개 화면에 없는 정보도 먼저 말합니다

공개 화면에는 등록한 증권 목록, 증권별 원본 줄, 원래 담보명, 계약 기준일이 나오지 않습니다. 특정 담보 금액이 어느 증권에서 왔는지 고객이 궁금해하면 공개 화면만으로 답을 만들지 말고 설계사 내부 자료와 원문 증권을 다시 확인합니다.

기준 금액과 부족·적정·넉넉 등급도 공개 화면에 포함되지 않습니다. 고객 상황에 맞는 기준을 따로 논의했다면 그 대화와 공유 링크의 사실 표를 구분하세요. 공개 화면의 숫자가 크거나 작아 보인다는 이유로 상품이나 계약 변경 방향을 제시하지 않습니다.

## 4. 화면을 본 고객의 질문을 남깁니다

고객에게 “이해하셨죠?”라고 묻기보다 공개 화면에서 함께 볼 질문을 하나씩 남깁니다.

- 월 보험료와 총 납입 보험료 가운데 다시 확인할 값이 있나요?
- 공유 당시 담보 중 이름이나 보유 금액이 궁금한 항목이 있나요?
- 화면에 `-`로 보이는 보험료가 있다면 원문에서 함께 확인할까요?
- 특정 담보 금액이 어떻게 모였는지 설계사 내부 자료로 다시 볼까요?
- 설명을 들은 뒤 추가로 확인하고 싶은 문서가 있나요?

질문에 바로 답하기 어렵다면 추측하지 않습니다. 확인할 담보 이름, 설계사가 볼 원문, 다시 답할 날짜를 짧게 적으세요. 고객의 질문이 공개 화면에 자동 저장된다고 말하지 말고, 실제 상담 메모와 회사 절차에 맞는 위치에 설계사가 기록합니다.

## 5. 공유 뒤 행동은 하나만 정합니다

링크를 보내기 전에는 다른 고객 정보와 내부 메모가 보이지 않는지 확인합니다. 고객에게는 “보험료와 보유 담보 금액을 확인한 뒤 궁금한 담보 하나를 알려주세요”처럼 한 가지 행동만 안내하세요. 고객이 질문을 고르면 설계사가 내부 화면과 원문을 대조해 다음 설명을 준비합니다.

공유 링크는 고객이 등록된 사실을 같은 화면에서 확인하도록 돕는 자료입니다. 기준이나 등급을 대신 전달하려 하지 말고, 화면에 보이는 보험료와 보유 금액을 설명한 뒤 질문을 이어가세요.

**오늘 할 일: [인파 보장분석 흐름](https://www.inpa.kr/solutions/policy-analysis)에서 원문과 내부 기준을 먼저 확인한 뒤, 가상 고객 공유 화면으로 `월 보험료 → 총 납입 보험료 → 공유 당시 담보 → 보유 금액 → 질문 하나`를 차례로 말해보세요.**
