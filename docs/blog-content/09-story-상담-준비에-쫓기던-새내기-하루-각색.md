# 상담 준비가 흩어질 때, 가상 업무 사례

<!-- blog-body -->

이 글의 ‘한 설계사’는 실제 인물이나 고객 후기가 아닙니다. 여러 설계사가 겪을 수 있는 업무 장면을 이해하기 쉽게 합쳐 만든 가상 사례입니다. 수치로 성과를 약속하지 않고, 기록이 흩어졌을 때 어떤 순서로 다시 모을 수 있는지만 보여드립니다.

한 설계사는 다음 날 상담을 앞두고 메신저, 휴대전화 메모, 종이 증권 사진을 번갈아 봅니다. 고객이 지난 통화에서 무엇을 궁금해했는지, 어느 증권을 먼저 확인하기로 했는지, 약속 시간은 바뀌지 않았는지가 서로 다른 곳에 적혀 있습니다. 자료는 있지만 상담의 시작점을 한눈에 잡기 어렵습니다.

## 상담 전 흐름을 한 줄로 세웁니다

설계사는 자료를 새로 만들기보다 확인 순서를 정했습니다.

1. 고객 기록에서 최근 대화와 다음 행동을 확인한다.
2. 고객이 전달한 증권만 모아 계약 정보를 확인한다.
3. 담보를 공통 항목으로 정리하고 연결이 애매한 부분을 표시한다.
4. 고객에게 물어볼 질문과 원문에서 확인할 조건을 나눈다.
5. 상담 일정과 이후 할 일을 같은 고객 기록에 남긴다.

![흩어진 메모와 증권을 고객 기록, 보장 정리, 다음 행동으로 모으는 가상 흐름](/blog-assets/상담-준비에-쫓기던-새내기-하루-각색/workflow-before-after.webp)

이 순서에서 중요한 것은 모든 정보를 많이 저장하는 것이 아닙니다. 이번 상담에 필요한 자료만 모으고, 병력이나 식별정보처럼 민감한 내용은 목적과 전달 방법을 확인한 범위에서 다뤄야 합니다.

## 자동 정리는 질문을 찾는 데 씁니다

설계사는 증권의 담보명을 공통 보장 항목에 연결한 화면을 봅니다. 연결되지 않은 담보는 직접 확인 대상으로 남기고, 연결된 담보도 원래 이름과 금액을 대조합니다. 기준이 없는 영역에는 보유 금액만 표시하고, 색이나 등급으로 판단하지 않습니다.

상담 질문도 결론 대신 확인형으로 바꿉니다.

| 화면에서 본 것 | 고객과 확인할 질문 |
|---|---|
| 같은 항목에 여러 담보가 연결됨 | 각 담보의 지급 조건과 기간을 함께 볼까요? |
| 금액이 없는 항목이 있음 | 기준을 정할 때 우선순위로 보는 상황이 있나요? |
| 연결되지 않은 담보가 남음 | 증권 원문과 약관에서 범위를 다시 확인할까요? |
| 갱신형과 비갱신형이 섞임 | 앞으로의 납입 시점과 변동 조건을 나눠 볼까요? |

## 상담 뒤에는 다음 행동만 분명히 남깁니다

상담을 마친 설계사는 긴 후기를 쓰지 않습니다. 고객이 확인하기로 한 문서, 설계사가 답하기로 한 질문, 다음 연락 날짜를 짧게 남깁니다. 고객 단계가 바뀌었다면 그 변화도 기록하고, 보류를 선택한 고객에게는 정한 날짜 전까지 반복 연락하지 않습니다.

## 흔히 놓치는 점

- 자동으로 정리된 담보를 증권 원문과 대조하지 않고 상담 자료로 확정하는 것
- 고객의 민감한 정보를 메신저, 메모, 개인 저장소에 중복해 옮기는 것
- 다음 행동에 담당자와 날짜를 적지 않아 약속의 주체가 흐려지는 것
- 가상 합성 사례를 실제 고객 후기나 성과 사례처럼 소개하는 것

증권 정리의 출발점은 [보험 증권에서 먼저 확인할 다섯 가지](/blog/보험-증권-보는-법-3분-체크리스트)에서 확인하세요. 고객과 약속한 후속 행동을 관리하는 방법은 [보험 상담 뒤 기록과 다음 연락](/blog/보험-상담-후-기록-다음-연락)으로 이어집니다.

## 그대로 써보는 상담 전 메모

- 고객이 오늘 확인하고 싶은 것:
- 받은 증권과 기준일:
- 원문 확인이 필요한 담보:
- 고객에게 물어볼 질문:
- 상담 뒤 서로 하기로 한 일:
- 다음 연락 날짜와 방법:

인파에서는 고객 기록, 증권 자동 정리, 보장 분석, 일정과 다음 행동을 한 흐름에서 확인할 수 있습니다. 여러 화면에 흩어진 준비물을 고객별로 모으고 싶은 설계사에게 맞는 사용 방식입니다.
